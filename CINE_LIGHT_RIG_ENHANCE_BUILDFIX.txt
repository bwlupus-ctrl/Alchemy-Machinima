E1 + E2 (alcinelightrig.cpp — the gobo texture fetch) — likely one root cause
=============================================================================
MIPMAP_YES is `const bool MIPMAP_YES = true;` defined in indra/newview/llviewertexturelist.h:41.
alcinelightrig.cpp includes llviewertexture.h but NOT llviewertexturelist.h, so MIPMAP_YES is
undeclared, which makes the whole getFetchedTextureFromFile(...) call ill-formed and cascades into the
C2593 'operator =' ambiguous at line 187 (assigning the malformed expression to
LLPointer<LLViewerFetchedTexture> cache[index]).

FIX: add `#include "llviewertexturelist.h"` to alcinelightrig.cpp (with the other includes). That
declares MIPMAP_YES (E2) and, by making the call well-formed, should resolve the operator= ambiguity
(E1/187). The working callers in llviewertexturelist.cpp use this exact API, e.g.
`getFetchedTextureFromFile("white.tga", FTT_LOCAL_FILE, MIPMAP_NO, LLViewerFetchedTexture::BOOST_UI)`.
If the operator= ambiguity SURVIVES after the include (it shouldn't), it means getFetchedTextureFromFile's
return type doesn't assign cleanly to LLPointer — in that case store the raw return in a local
`LLViewerFetchedTexture*` first and assign that, and say what you did. Keep the boost level you have
(LLGLTexture::BOOST_NONE) unless it is itself ambiguous — if so, match the working callers'
`LLViewerFetchedTexture::BOOST_UI` idiom.

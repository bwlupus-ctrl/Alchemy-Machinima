=============================================================================
WHAT & WHY
=============================================================================
The rig centres on the subject's CHEST JOINT (an animated bone), so an in-place animation that swings
the torso drags the lights with it. Add a toggle so the operator can centre on a STABLE body position
instead. User decision (fixed): two modes, default = Skeleton (unchanged behaviour).

  - **Skeleton (mode 0, DEFAULT)** — current behaviour EXACTLY: centre = chest joint world position
    (alcinelightrig.cpp:1092, `scaledPoint(avatar, chest->getWorldPosition(), subject_scale)`), with the
    existing fallback to render-position when there is no chest joint. Lights follow the pose.
  - **Body-stable (mode 1)** — centre = the avatar's render position + fixed chest height, IGNORING the
    animated chest bone, so lights stay put while the subject animates in place. This is EXACTLY the
    expression the existing no-chest fallback already uses (alcinelightrig.cpp:1098-1101:
    `scaledPoint(avatar, getRenderPosition() + LLVector3(0,0,1.2f), subject_scale)`).

=============================================================================
THE CHANGE (controller-only; NO model/shader/pipeline; NO new math)
=============================================================================
1. SETTING: add `CineLightRigTrackMode` (S32, default 0) to settings.xml. 0 = Skeleton, 1 = Body-stable.

2. CONTROLLER (alcinelightrig.cpp, the centre computation ~1088-1106): read the mode
   (LLCachedControl<S32>, sanitize/clamp to [0,1]). Branch:
   - Mode 0 (Skeleton): the current code path, UNCHANGED — read the chest joint, fall back to
     render+1.2 if absent. Must be BITWISE-identical to today when the setting is 0 (default), so a
     literal early branch that leaves the existing lines untouched is ideal.
   - Mode 1 (Body-stable): SKIP the chest-joint read entirely and take the render-position path — i.e.
     force `have_joint = false` (or otherwise route directly to the existing
     `scaledPoint(avatar, getRenderPosition() + {0,0,1.2f}, subject_scale)` expression). Do NOT
     duplicate the expression — reuse the existing fallback code so scaledPoint (foot-pivot scale),
     OffsetZ (:1112), and damping (:1116+) all still apply identically in both modes. The ONLY
     difference between the modes is whether the chest joint is consulted.
   Sanitize: a non-{0,1} or out-of-range value -> 0 (Skeleton). Subject-lost / no avatar path unchanged.

3. UI (panel_cine_light_rig.xml + alpanelcinelightrig.cpp): add a 2-option combo bound to

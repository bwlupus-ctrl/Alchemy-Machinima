PART 1 — MIRROR must flip SIDE-TO-SIDE (across the avatar's facing), not FRONT-TO-BACK
=============================================================================

DIAGNOSIS (established by reading the code):
- computeLive (alcinelightrigmodel.cpp:458) does `yaw = mMirror ? -base.mYawDeg : base.mYawDeg`.
  Negating yaw reflects the light across the WORLD X-axis (yaw 0).
- The orbit is world/region-framed: off_x = r*cos(yaw), off_y = r*sin(yaw)
  (alcinelightrigmodel.cpp:538-539) added to the emitter's GLOBAL position X/Y — so yaw 0 =
  region-east, yaw 90 = region-north. The rig has no avatar-facing sense (by the base design).
- Therefore mirror reflects across a FIXED WORLD axis. Whether that looks like a left/right cheek
  swap or a front/back flip depends entirely on which way the avatar faces. Avatar facing world-Y:
  a front-left light at yaw 45 mirrors to yaw -45, which relative to the face is front->BACK on the
  same side. That is the reported bug.

THE FIX: mirror must reflect across the avatar's FACING azimuth, not world zero:
    mirrored_yaw = wrap180(2 * facing_azimuth_deg - base.mYawDeg)
When facing_azimuth_deg == 0 this is exactly `-base.mYawDeg` (today's behaviour), so a
world-aligned avatar and EVERY existing test are unchanged. Mirror-twice stays identity:
2f - (2f - y) = y. Only MIRROR becomes face-aware; base yaw and Orbit Yaw stay world-relative
(do NOT rotate the whole rig — the user explicitly wants only the mirror to change).

IMPLEMENTATION:

Model (alcinelightrigmodel.h / .cpp):
- Add `F32 mFacingAzimuthDeg = 0.f;` to `Transforms`.
- In `sanitizeTransforms`: if `!std::isfinite(mFacingAzimuthDeg)` set 0.f, then wrap180 it into
  (-180,180]. (Any finite angle is valid; it is an azimuth.)
- In `computeLive`, replace the mirror line with:
    const F32 yaw = safe_transforms.mMirror
        ? wrap180(2.f * safe_transforms.mFacingAzimuthDeg - base.mYawDeg)
        : base.mYawDeg;
  Keep the subsequent `wrap180(yaw + safe_transforms.mYawDeg)` (orbit applies after the reflect).
- The default mFacingAzimuthDeg = 0 makes this bitwise-identical to the current `-y` mirror, so the
  existing mirror-invariance tests pass UNTOUCHED. Do not alter those tests; ADD new ones (below).

Controller (alcinelightrig.cpp):
- The transforms fed to computeLive are built per-frame. After the anchor avatar is resolved in the
  tick (the `LLDirectorCast::instance().resolve(mAnchor)` result, ~line 1010 region), compute the
  facing azimuth in the SAME region frame the orbit uses and set it on the transforms:
      LLVector3 fwd = LLVector3(1.f, 0.f, 0.f) * avatar->getRotation();
      F32 facing = atan2f(fwd.mV[VY], fwd.mV[VX]) * RAD_TO_DEG;   // region frame: X=east, Y=north
      if (!std::isfinite(facing)) facing = 0.f;
      transforms.mFacingAzimuthDeg = facing;
  If no avatar is resolved (subject lost), leave mFacingAzimuthDeg = 0 (mirror falls back to the
  world-X reflection — acceptable degenerate, matches "no subject" everywhere else).
- Sample facing LIVE per frame (consistent with the per-frame centre/scale sampling). Do NOT persist
  it; it is ephemeral like subject scale — no settings key, no scene field.
- VERIFY the rotation source: `avatar->getRotation()` must give the avatar BODY facing in the region
  frame that off_x/off_y live in. If getRotation() is not the body facing (e.g. it returns identity
  for an attachment-style object or the wrong frame), use the root-joint world rotation instead and
  say which you used and why. This frame match is the one thing most likely to be subtly wrong — get
  it right and state your reasoning.

Tests (alcinelightrigmodel_test.cpp) — ADD (do not modify existing mirror tests):
- facing = 0: mirror(y) == -y for a spread of y (bit-identical to the old behaviour).
- facing = 90: mirror(45) == 135, mirror(135) == 45, mirror(-45) == -135 (reflect across 90).
- mirror-twice identity at facing = 37 (a non-trivial angle): computeLive(mirror) twice == original.
- non-finite / unwrapped facing sanitises (e.g. facing = 720 wraps; facing = NaN -> 0 -> plain -y).
Each test must FAIL if the reflection reverts to `-y`; state that explicitly.

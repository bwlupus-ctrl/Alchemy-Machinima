M2 (MUST-FIX) — test<13> asserts exact 1.0 on a value that is 1 ULP low (TEST-ONLY; code is correct)
=============================================================================
tests/alcinelightrigmodel_test.cpp, in test<13>, two assertions:
    ensure_equals("unit red saturates instead of wrapping",  composed.mProj[0].mSR, 1.f);   // ~:1338
    ensure_equals("unit blue saturates instead of wrapping", composed.mProj[0].mSB, 1.f);   // ~:1343
The emitted sRGB is linearChannelToSRGB(1.0f) = 0.99999994039f (exactly 1 ULP below 1.0), because
saturation is clamped in LINEAR space then re-encoded to sRGB. ensure_equals on F32 is EXACT (no
tolerance), so these throw and test<13> fails at runtime. The COLOUR CODE IS CORRECT — do NOT change
the colour math, the transfer functions, or render(). Fix ONLY the two assertions to use the tolerance
idiom already used ~45 lines above in this same test (the `std::fabs(...) <= 0.002f` / 2e-3 pattern):
    ensure("unit red saturates instead of wrapping",  std::fabs(composed.mProj[0].mSR - 1.f) <= 2e-3f);
    ensure("unit blue saturates instead of wrapping", std::fabs(composed.mProj[0].mSB - 1.f) <= 2e-3f);
Keep the assertion messages. This preserves the intent (channel saturates rather than wraps) without
the impossible exact-equality.

=============================================================================
WHAT THE FEATURE IS
=============================================================================

The in-world LSL "Cinematic Studio" light rig, re-implemented as a client-side viewer
feature: local, prim-free cinematic lights orbiting a subject. 4 logical lights
(KEY/FILL/RIM/BG), each with yaw/pitch/colour-profile/EV/beam/on, driven from a pristine
base setup through mirror/orbit/pitch transforms, with 0.9s eased transitions and 33
animated FX effects. No in-world prims, no script, no rez rights, works on no-rez parcels.

Anchors to the user's own avatar OR any Director cast member.
Controls live in BOTH a new Director Console "Lights" tab AND a standalone floater,
in lockstep (settings-backed controls, per the design doc §3.5).

=============================================================================
THE THINGS MOST LIKELY TO GO WRONG — get these right
=============================================================================

1. DETERMINISM. Every one of the 33 FX must be a PURE FUNCTION of
   (effect, seed, presentation_time). No wall clock. No frame counters. No llFrand
   equivalent with hidden state. This fork renders takes at non-realtime rates via
   Temporal Capture, so a re-render of the same take must produce bit-identical light.
   Use the counter-based hash the design doc specifies. Design doc §5.
   The "latch" effects (Stage Debut, Explosion, Supernova) are the highest
   silent-divergence risk -- design doc §5.3 tells you how to handle them.

2. THE DERIVED-STATE INVARIANTS. The whole point of the LSL v20 architecture:
   live state is RECOMPUTED from base x transforms, never accumulated in place.
     - mirror twice           == bitwise identity
     - orbit +15 then Reset   == exactly the loaded setup
     - switching setups       == keeps current aim
   These are testable invariants and the TUT test must assert them (design doc §4.3).

3. THE OFF PATH MUST BE PROVABLY INERT (CLAUDE.md rule 1). The six pipeline.cpp gate
   edits must be no-ops when the feature is off. Teardown must remove every emitter
   object AND every light-set entry -- on logout, teleport, region change, and shutdown.
   Handle LLApp::isExiting(). A dead emitter left in mLights is a crash.

4. POSITIONAL DATA. settings.xml keys, the profile table (24 entries), the beam table
   (3 entries), and the FX tables are positional. After writing them, VERIFY BY COUNTING
   and cross-check the values against the LSL reference. "It compiles" proves nothing
   about positional data (CLAUDE.md rule 6). Note the design doc flags a latent LSL bug:
   beam index 3 is out of range and yields fov 0 -- do NOT copy that bug.

5. Emitter setup differs from the ghost-proxy template in specific ways
   (mbCanSelect = FALSE, fixed 0.25m scale, FORCE_INVISIBLE re-asserted per tick,
   setPositionGlobal). Design doc §3.2. Follow it exactly -- scale participates in
   projector optics.

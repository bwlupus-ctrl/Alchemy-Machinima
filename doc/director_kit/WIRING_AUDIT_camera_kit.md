## Range policy (coordinator decision; overrides the clamp-only rule where they conflict)

- A consumer clamp that is only a safety ceiling far above the authored legacy range keeps the legacy range. Operator-level clamps in `llcameraoperator.cpp` fall in this group: Operator gains stay 0..2 (clamp 0..10 via `vc_mode_safe`), Blend time stays 0..5 (clamp 0.01..60, `llcameraoperator.cpp:1041`), Pan, Tilt and Roll amounts stay 0..10 (clamp -100..100, `llcameraoperator.cpp:1257`, `:1260`, `:1263`).
- A range is widened only where the legacy or mockup range hides consumer-accepted, usable values: duration and distance floors of 0.1 (shared one-shot clamp `cc_progress_raw`, `llcinematiccamera.cpp:921`), Fisheye FOV 0.05 (clamp 0.05..4.0), Pedro FOV 5..175, Orbit zoom 0.1..4.0, Orbit minimum radius 0.01 (`llviewerjoystick.cpp:2796`), Director time speed 0..8 (`pipeline.cpp:18809`), switcher interval floor 0.1 (`aldirectorswitchermodel.cpp:36-38`).
- Never beyond the clamp. Shared writers carry the same range on every page: Vertigo and Arc duration are 0.1..60 on Shot and Moves; CinematicCamFrameOffsetUp is -20..20 with its home on Frame and Orbit, matching the legacy range on Operator (which now links to it).

## Fixes made in this batch

- Mockup ranges and combo values changed in `director_mockup_data.json` (the table's "changed" column marks each row): duration floors, distance floors, Fisheye FOV, Orbit zoom and radius, Pedro FOV, Time speed, switcher interval, Movement values `[0,1,2,3,4,5,6,100]`, Look combo `1..9`, Auto ease and freeze curves `0..32,100` (Custom is 100), switcher slot mode skipping 40, secondary subject `1..4`, flight model `[0,2,1]`, frame aspect ratio float list, settle curve `0..32,100`, CinematicCamJoint values as joint names (the setting is a String; index values were wrong).
- F32 combo: the frame aspect ratio is an F32 setting, so the combo is code-bound. It writes the chosen ratio and mirrors the setting back under a recursion guard (`llfloaterdirector.cpp`, `bindFrameOrbitPage`).
- Switcher selection order: the Boolean setting `DirectorSwitcherSequence` is a toggle, not a combo (Sequence is on).
- Re-solve now (`auto_frame_resolve`) was not bound anywhere in v2. It is bound to `LLCinematicCamera::requestAutoReframe()` (`llcinematiccamera.cpp:490`).
- Frame and Orbit watch list adds `CinematicAutoFrameEnabled` and `FlycamOrbitEnabled` (generator key `watch_extra`, read in `director_kit_gen.py` `page_attrs`).
- Reset Mode and Reset All are static `ALPanelCineCamParams::resetModeToDefaults()` and `confirmResetAll()`, with the same settings and the same confirm dialog. The instance handlers delegate to them.
- Shake look combo: static `ALPanelCineCamParams::applyShakePreset(index)`. The v1 `onShakePresetSelected` delegates to it.
- Drone preset: the commit applies the preset through `LLViewerJoystick::applyDronePreset(0..4)`; Custom is not applied. On release it calls `markDronePresetCustom()`.
- Temporal presets: the five buttons write the same two settings as `ALPanelTemporalCapture::onClickScalePreset`. Live to Manual when the scale is not 1 is driven from the TemporalWorldScale setting signal (`onScaleCommit` rule), so reset, paste and preset follow it too.
- Start Zolly (`llfloaterdirector.cpp`, `onClickZolly`): not a swap bug, so the handler is unchanged. The legacy help text (`floater_director.xml`, zolly_direction) says Dolly out moves near to far and Dolly in moves far to near. `onClickZolly` maps that to Start and End. The consumer `patternDollyZoom` (`llcinematiccamera.cpp:1160-1165`) travels from Start to End and never reads `CinematicCamVertigoDirection`. The real hazard is a side effect: Start Zolly overwrites the shot page's Start and End distances and forces the end mode to Hold. Reported, not changed.

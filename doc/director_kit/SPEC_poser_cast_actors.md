# Poser: Director Cast actors, local only

Plan only, 2026-10-17. No implementation or build. References describe this checkout; paths below are relative to `indra/newview/` unless prefixed `indra/llcharacter/`.

## Contract and scope

Keep self and owned Animesh working. Add live, unmuted, same-region Director Cast residents and Cast Animesh within the existing **strictly less than 50 m** radius. Cast membership is the operator's explicit opt-in to local direction; it is not simulator animation permission or an animation-export right. Crowd, friends, subjects alone, Dance Ball roster membership, and an empty Cast never authorize another avatar. Do not automatically add anyone to Cast. Ghost Studio drive modes remain outside this change.

Use the existing poser, pose files and tools. Label added rows `Roddra Venus (Cast, local only)` (equivalent localized Animesh label); UUID remains the value. Add a short explanation beside the selection/Start controls: “Cast posing affects only this viewer. Other viewers see the actor's normal animations.” Labels must update when names/membership change. Stop always remains available for an owned session, even when Start is no longer allowed. Missing selection disables controls and clears tools; no silent fallback to self.

Add one persisted Boolean kill switch, **`DirectorPoserCastEnabled`**, default true: Cast membership is already the opt-in. False immediately releases this extension's active Cast sessions, cancels pending loads, removes added rows, and blocks new starts in Poser and Switchboard's Cast pose path. Self/owned behavior stays available. Retire `BDMergePoserAnyAvatar` as an authorization input in both callers; neither a saved true value nor a command-line setting may bypass Cast. Leave its declaration deprecated if needed for configuration compatibility; do not migrate “any avatar” into a crowd entitlement.

## Session ownership and release

Keep a small model-owned ledger of active **Cast pose sessions**, independent of list rows/floater visibility: canonical ID, runtime object identity, skeleton generation, owner token (Poser or Switchboard), registered motion ID, acquisition snapshot, pending-load generation. Share this ledger across `FSPoserAnimator` instances; the current static motion map alone is not ownership. Acquisition is atomic, failed starts unwind completely, and only the matching token may edit/release. Existing self/owned paths need regression coverage rather than a general animation-engine rewrite.

Service active-session validity from the main-thread world tick beside `ALDanceBall::tick()` (`llappviewer.cpp:5604`), before object animation updates. Check only active sessions. Cast/mute/setting notifications mark invalidation; model service also catches range, region, missing objects and skeleton changes. Do not release synchronously from a Cast changed callback: `lldirectorcast.cpp:1176` signals before `:1178` rebuilds its index. Release at the next safe model boundary using the finalized roster, before another pose write. UI list refresh is revision-driven/on demand or at most 2 Hz while visible, never work in `draw()` (`fsfloaterposer.cpp:342`; CLAUDE.md UI rules).

| Event | Required behavior |
| --- | --- |
| Remove from Cast, mute, kill switch off, or reach/exceed 50 m | Cancel pending work, release owned pose, clear selected tools, remove added row. Re-add/unmute/return in range requires a fresh explicit Start. |
| Actor leaves region, derezzes or logs out; operator teleports/disconnects/logs out | Release while the old object is still usable; otherwise discard ledger/cache without dereferencing it. No resume on a new object with the same UUID. |
| Skeleton rebuild/appearance change or control-avatar regeneration | Release before old joints are destroyed where possible; invalidate handles/snapshot and require Start on the rebuilt skeleton. Never restore old joint pointers into a new skeleton. Relevant destruction entry: `llvoavatar.cpp:925`. |
| Stop, Stop All, floater close/destruction | Release ledger sessions, including targets no longer listed. Cast sessions always stop on close; the legacy “Stop posing when closed” preference can still govern self/owned. Switchboard-owned sessions follow its own transport release, not the Poser floater's close. |
| Scene load/restore/reset | Release all outgoing Cast pose sessions even when incoming Cast contains the same UUID. Do not restart poses on restore. |

One idempotent release routine, permitted **after eligibility has been lost**:

1. Invalidate token/load generation first. Bind retries to the originally requested actor and session, not whichever row is selected later (`fsfloaterposer.cpp:1127`, `:1131`, `:1136`). Cancel on selection/session change. Reject late completions and mouse-up callbacks.

3. On the same still-live skeleton, restore any temporary render overlay before touching underlying joints. Stop only the session's registered motion immediately via the local `LLCharacter` path, ensuring deactivation runs even if hidden/paused/out of range. Current stop defaults to easing, while `FSPosingMotion` has 0.5 s ease-out (`fsposingmotion.h:59`); teardown must not wait for visible animation updates.
4. Deactivation currently reverts all joints/collision volumes (`fsposingmotion.cpp:121`, `:123`; `fsjointpose.cpp:251`) to **mutable bases** (`fsjointpose.h:350`). Do not blindly remove a controller motion while external code still holds its pointer. Dead-object cleanup is bookkeeping only. Add pre-destruction/rebuild hooks where needed; a periodic pointer check alone cannot guarantee safe teardown.

## Animation conflicts: bounded policy

For this extension, **one local body driver per Cast actor**. Keep a narrow shared busy/ownership check, not a new priority mixer. A second driver is rejected/skips that actor with a visible reason; no silent takeover or automatic resume. Other actors keep running.

| Driver/layer | Policy and evidence |
| --- | --- |
| Simulator animations/AO/sits | Continue receiving/running them underneath; do not alter `mSignaledAnimations` or stop/restart their UUIDs. Pose affects selected joints through existing motion blending; unposed joints remain animated. Do not globally pause the controller. On release current server animation wins immediately. `FSPosingMotion` advertises `ADDITIVE_PRIORITY` with `NORMAL_BLEND` (`fsposingmotion.h:61`); per-joint bases/priorities also matter, so test rather than claim every bone always wins. |
| Switchboard | Exclusive ownership is mandatory: its private animator reaches the same static registered motion (`aldirectoranimswitcher.cpp:297`, `:338`, `:347`). Check tokens on acquire/load/release, gate Cast poses through the shared predicate (`:269`), and skip busy Cast targets for animation slots too (`:410`). Its Stop must not stop a Poser-owned motion. |
| Dance Ball | Reject Poser Start while that actor has an active/pending/releasing Dance Ball drive; while posed, Dance Ball skips it as IN_USE and cannot auto-join/reclaim it. Check actual runtime, not just roster membership; hook near acquisition (`aldanceball.cpp:1194`) and per-actor drive (`:1555`). Resume requires an explicit actor play/start after pose release. |
| Actor Mover | Reject Start while actor is driving, including pending stagger starts; reject new path/walk starts for posed actors. Preserve unrelated placement/marks, but disable competing root manipulation during the session. Entry points: `llactormover.cpp:3862`, `:4324`; driving query `llactormover.h:677`. No path is implicitly stopped or resumed. |
| Poser's local animation Play | Do not add a second local body animation to an active Cast pose session, or acquire a pose while owned playback remains active (`fsfloaterposer.cpp:2501`). Release before switching mode. Track and stop only locally owned playback; never stop a server-signaled UUID merely because it appears in the animation list (`:2524`). |
| Pose Polish / Gaze | Retain existing composition: blended pose → Polish → Director camera gaze, otherwise Actor Mover gaze (`llvoavatar.cpp:5815`, `:5840`). These can change the final posed appearance; UI help says so. Do not rewrite priorities or globally disable settings. Restore/rebase render-only Gaze saves before acquisition/release (`llvoavatar.cpp:5704`) and clear this actor's temporal history on transitions. |
| Stepped | Remains the final presentation hold, so edits may appear on its next capture. Restore overlays before pose capture/release and invalidate this actor's held joints **and attachment** history on transitions; ordinary edits follow its selected rate. Hooks: `alsteppedanimruntime.cpp:865`, `:961`, `:1005`, `:1178`; frame application `llappviewer.cpp:5842`. Add a targeted invalidation API; do not disable Stepped globally or leave a held posed frame after Stop. |

## Firestorm assumptions and persistence audit

- **Local-only proof is scoped.** Animator creates/starts a local `FSPosingMotion`; only self calls `gAgent.stopFidget()` (`fsposeranimator.cpp:1647`). Non-self `LLVOAvatar::startMotion/stopMotion` go to `LLCharacter`; AO network requests are in self branches (`llvoavatar.cpp:7405`, `:7419`, `:7449`, `:7463`). Use explicitly local calls for new Cast lifetime operations. Audit async loading/default-motion side effects too; `startDefaultMotions()` honors Animesh's disable flag but calls animation reconciliation (`llvoavatar.cpp:2170`, `:2199`). Do not add simulator pose/animation, permission, agent, attachment, or transform messages. Network asset reads are distinct from publishing a pose.
- **Non-self keyframes are supported, with hazards to verify.** `FSPosingMotion::onInitialize()` binds the supplied character's joints (`fsposingmotion.cpp:39`); no self-only requirement is apparent. Non-self hidden/LOD updates and the 500-pixel-area activation threshold (`fsposingmotion.h:37`, `:66`; `llvoavatar.cpp:5737`) need in-world coverage. Capture uses `mPlayingAnimations` and `LLKeyframeMotion` (`fsposestate.cpp:19`); it does not capture every local Dance Ball/Actor Mover motion, reinforcing exclusivity. Existing downcasts of arbitrary keyframes to `FSPosingMotion` (`fsposingmotion.cpp:291`, `:360`) are unsafe assumptions to address with proper base-class sampling or a checked helper before extending recapture use; do not rely on non-null `static_cast` as validation. State replay's missing-motion start/stop fallback (`fsposestate.cpp:206`) must not stop an already-running server/other-owner motion; load/sample without taking its playback ownership.
- **Own Poses means disk files**, not poses belonging to the selected resident (`fsfloaterposer.cpp:462`; `skins/default/xui/en/floater_fs_poser.xml:2170`). Keep this list and existing hand presets shared. XML save/load and BVH output operate on the selected skeleton (`fsfloaterposer.cpp:692`, `:3024`); saving writes disk, not the simulator. Preserve original-work/base-zero BVH rules and XML owned-animation filtering (`fsfloaterposer.cpp:710`; `fsposestate.cpp:98`, `:235`). Cast does not set `ignoreOwnership=true` on save. Existing load can mark assets owned in a static cache (`fsposestate.cpp:150`); do not let imported references confer export rights on captured third-party animations. Fix/isolate that cache behavior if exposed by this path; do not weaken it for convenience. Diffs lacking unowned bases may be incomplete; disclose existing limitation and test T-pose-authored files.
- **No scene schema expansion.** Cast membership already serializes; live Cast poses, snapshots, active tokens and pending loads do **not** persist. Save leaves live poses running but captures none of them; load releases them before membership replacement, including restore/undo routes to `LLDirectorCast::applySceneData()` (`lldirectorcast.cpp:2232`, `:2367`). Put release at the model boundary, not only the console (`llfloaterdirector.cpp:4315`). Existing saved pose files and Switchboard bank pose references remain usable by explicit action. Loading a scene never acquires a skeleton. The kill switch is a preference, outside scene/look preset ownership.

## Delivery slices, risks and verification

These are small implementation/review slices of one feature; ship only when all are complete. No code/build is authorized by this document.

1. Shared Cast predicate, kill switch, token ledger, local acquisition/release and lifecycle hooks; validate negative authorization and pointer lifetime first.
2. Wire discovery/insertion, every handler, tool cancellation, original-target load retries and localized labels; add driver conflict checks and per-actor overlay invalidation. Deliver the reachable UI together with the safety wiring.
3. Adversarial source review and targeted automated checks, then a separately authorized build and in-world matrix. Reject the change if clean release or local-only behavior cannot be demonstrated; do not ship a filter-only patch.

Primary risks: shared motion ownership, stale skeleton/joint pointers, mutable-base restoration, hidden/paused deactivation, repeated async load after revocation, and overlays restoring stale poses. Bound the patch to these paths; no scene-pose format, crowd posing, generic arbitration framework, or whole-skeleton reset.

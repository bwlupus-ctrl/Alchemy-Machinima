# Director Settings value-wiring audit

The generated non-rail Settings page is opened by the top-bar gear and indexed by the kit search. All preferences persist in global settings. The two recovery preference rows have bulk_reset=false, so page/card resets leave them alone. The Theme row is bulk-resettable: a page or card reset returns it to Default.

| Control | Setting / type | Values / range | Handler | Read-back |
|---|---|---|---|---|
| settings_recovery_mode | DirectorRecoveryMode / S32, Persist 1, default 0 | 0 Ask me; 1 Restore automatically; 2 Don't restore (keep the backup) | ALKitSettingBinding typed write; offerSceneRecovery consumes it (ALDirectorQol::loginAction); recovery-service signal clears the old notification ignore when changed | ALKitSettingBinding setting signal refreshes combo |
| settings_crash_backups | code-populated combo (no setting); item value = backup file name in <scenes>/crash_backups/ | newest first, newest 5 (ALDirectorQol::sortCrashBackupsNewestFirst); label = date/time + scene name when known | refreshRecoveryControls repopulates only when the file list changes; empty list shows "No crash backups" and disables the combo and both buttons | refreshed every 1 s real time (sceneRecoveryIdle) and after every restore, delete, move, prune and quarantine |
| settings_restore_backup | action | Restore... | requestRestoreCrashBackup -> DirectorConfirmRestoreRecovery (payload carries the exact path) -> onRestoreRecoveryConfirmed -> restoreCrashBackup(path): re-checks the file exists, reads it fully (unreadable = kept; opened + read + not parseable = renamed .corrupt, max 3), then loadScene("recovery", true, path); the backup file is NOT deleted | toast on success/failure; list refreshed |
| settings_delete_backup | action | Delete... | requestDeleteCrashBackup -> DirectorConfirmDeleteCrashBackup (payload carries the exact path) -> onDeleteCrashBackupConfirmed re-checks the file exists, then removes only that file | toast on failure; list refreshed |
| settings_recovery_help | readout | Autosave and backup explanation | generated text | static text |
| settings_add_self_at_login | DirectorAddSelfAtLogin / Boolean, Persist 1, default 1 (existing setting verified) | false / true | ALKitSettingBinding typed write; existing login cast enrollment consumer | ALKitSettingBinding signal |
| settings_reset_prompts | action | Reset 'don't ask again' prompts | DirectorRecoveryMode=0; resets ignores only for notification template names beginning Director | combo setting signal; Director notification forms become unignored |
| settings_theme | DirectorTheme / String, Persist 1, default "default" | Default (default); Second Life (second_life). Items come from app_settings/director_themes/*.xml, label per file, Default first (director_kit_gen theme_list rows) | ALKitSettingBinding typed write; ALDirectorTheme::init setting signal applies the theme live through LLUIColorTable::setLoadedColor, so colors.xml is not written | ALKitSettingBinding setting signal refreshes combo |
| btn_director_settings | shell action | Settings page | ALKitShell -> selectPage("director_settings_tab") | selected gear state and Settings page title |
| DirectorRestoreRecovery ignore checkbox | DirectorRecoveryMode / S32 | unchecked: ordinary Restore/Discard; checked Restore -> 1, checked Discard -> 2 (ALDirectorQol::rememberedRecoveryMode) | standard save_option ignore remembers chosen button; onRecoveryResponse reads response["ignore"] and selected option; Discard deletes only the one backup the prompt described (payload path), Restore never deletes, closing / ignoring / a Preferences-disabled prompt with no saved response keeps it (ALDirectorQol::promptAction) | Settings combo signal; autosave is never blocked by any recovery state |

The recovery notification uses the standard last-response ignore mechanism with an optional checkbox_label for the exact explanatory checkbox copy. Other notification labels retain their existing fallback. Autosave always runs (timer and shutdown): a previous session's live file is moved into crash_backups at login, and until that move succeeds autosave writes the alternate live file .director_recovery_2.xml instead of overwriting it. No other existing Director notification currently declares an ignore; the prefix-filtered reset also covers future Director ignores.

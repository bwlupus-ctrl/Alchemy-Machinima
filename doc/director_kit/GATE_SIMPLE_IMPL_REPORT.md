## Gate cookie rule

Each Gate projector stores its last successfully rendered content key. It includes Gate identity, program/from source ids, generations, publications and output availability, retained copy key, alpha, empty/black state, animated-effect phase bucket and Hz, destination aspect, projector settings revision and resolution. The effect bucket uses the already updated frame clock; Gate shader time uses that same bucket. Black normalizes obsolete source, alpha and effect inputs and renders opaque black directly, even when undemanded Gate texture publication is still pending.

`prepareGatePrismProjectorFeeds` is the sole Gate-cookie pass, invoked from one shared post-compose site in both camera/no-camera execution branches. It visits every Gate projector independently of demand and retained-copy backoff. A changed key renders once using `buildProjectorCompositeState`, the same retained-primary/incoming-output per-consumer blend used by faces; an unchanged key does no render. Only a successful render/mip publication accepts the key. Initial Gate binding also defers allocation to this pass. Cookie allocation failure retains the previous cookie/key and retries using the existing `deferRetry` delay (5/30 seconds), tracked separately per cookie so retained-copy backoff cannot stall alpha. Changed keys cannot bypass that retry deadline.

Removed Gate presentation refresh from `stepGate` and `composeGate`, `refreshGateProjectors`, `gatePresentationChanged`, the `mProducedFrame` guard, and Gate participation in the media animated pass. Gate ignores the shared camera/media dirty field. Ordinary camera scheduling/rendering and ordinary media dirty/publication/effect scheduling retain HEAD behavior; the media renderer is extracted into a shared helper with unchanged ordinary-media shader operations and clock inputs.

# RUN 135523 triage

Scope: `run_functional_20261011_135523/functional.csv`, v2 only. Diagnosis below is from the captured JSON and shipping code before the changes in this round. No build was run.

## Combo event path and exact break

`LLComboBox` creates its `LLScrollListCtrl` as a child, installs the list commit callback as `onItemSelected`, and disables commit-on-keyboard-movement (`indra/llui/llcombobox.cpp:136-147`). `showList()` fits and positions the list relative to the combo, clamps/translates it on screen, focuses it, shows it, and registers the **combo** as a popup (`indra/llui/llcombobox.cpp:675-768`). `LLPopupView::addPopup()` only records a handle; it does not reparent either object (`indra/newview/llpopupview.cpp:239-245`). Thus the run's `/popup_holder/ComboBox` down path means dispatch passed through the popup holder (`indra/newview/llpopupview.cpp:97-135`), not that the list's ownership changed. The opening button transfers capture to the list (`indra/llui/llcombobox.cpp:795-825`).

On an item press, `LLScrollListCtrl::handleMouseDown()` clears `mSelectionChanged` then calls `handleClick` (`indra/llui/llscrolllistctrl.cpp:2047-2063`); `handleClick` hits the row, calls `selectItemAt`, and captures the list (`indra/llui/llscrolllistctrl.cpp:2250-2305`). `selectItemAt` selects the enabled item, records `mSelectionChanged`, and commits immediately only when `mCommitOnSelectionChange` is true (`indra/llui/llscrolllistctrl.cpp:1937-2043`). Combo lists use the normal mouse-up path. `handleMouseUp()` releases capture, reselects at the release coordinate, and calls the list's `onCommit()` only if the release is inside `mItemListRect` (`indra/llui/llscrolllistctrl.cpp:2065-2087`). That list signal invokes `LLComboBox::onItemSelected`, which updates the label/value selection, hides the list, then calls the combo's `LLUICtrl::onCommit()` (`indra/llui/llcombobox.cpp:845-863`); `LLUICtrl::onCommit()` fires that control's `mCommitSignal` (`indra/llui/lluictrl.cpp:420-433`).

For `mode_combo`, the open list was `[269,1086,419,1124]`. Two 18 px rows plus 1 px borders make item index 1's local cell `[1,1,149,19]` from `getCellRect()` (`indra/llui/llscrolllistctrl.cpp:1881-1889`, row offset at `:2396-2399`), so its center is local `(75,10)`, screen `(344,1096)`. The item down therefore hit row 1 and captured the list. The harness then incorrectly reapplied its *opening-click* special case to this second capture and changed mouse-up to `mItemListRect.left-2,bottom-2`, local `(-1,-1)`, screen `(268,1085)` (`indra/newview/aluiperfselftest.cpp:3012-3023` before this fix). Mouse-up reached the captor but was outside both the row and `mItemListRect`; selection occurred on down, but no list commit fired. This exactly explains `down_handler=/popup_holder/ComboBox`, `up_delivered_to_allowed_captor=true`, unchanged `TemporalMode`, and `commits=0`.

The special outside release is now restricted to an opening `LLButton`; the item gesture keeps down/up at the calculated row center and records both the local cell and screen point (`indra/newview/aluiperfselftest.cpp:3005-3024,3384-3401`). This is the same path for legacy `mode_combo`, kit `cine_track_mode`, and the kit preset combo.

## Commit witness and preset strip

The counter is connected directly to the exercised control via `control->setCommitCallback` (`indra/newview/aluiperfselftest.cpp:3907-3915`). `setCommitCallback` appends a slot to that exact control's `mCommitSignal` (`indra/llui/lluictrl.cpp:1080-1085`); it is not attached to the list or an owner-only callback. The list commit reaches it through `LLComboBox::onItemSelected` as described above.

`preset_strip:rig_rim` is not a product wiring bug. The strip attaches `onSelect()` to the combo (`indra/newview/alkitpresets.cpp:225-232`), the provider maps `b:Subtle Edge` to `applyPresetByName` (`indra/newview/alpanelrigrim.cpp:32-55`), and that preset writes `CineRigRimMasterGain=0.6` plus the remaining preset fields (`indra/newview/alrigrimcontroller.cpp:283-312,420-430`). Run 135523 started at 0.6, so even a repaired click needed an alternate pre-state to prove the effect. The manifest now supplies one (`scripts/code_tools/director_functional_manifest.py:807-833`).

## Gel/gobo rows

These are harness/manifest-resolution failures, not missing product items. Per-light gobo lists add `None` followed by a disabled header; gel lists add `None` followed by the disabled `Colour Temp` separator, then enabled values (`indra/newview/alpanelcinelightrig.cpp:999-1036`). Fixture gels have the same index-1 separator (`indra/newview/alpanelcinelightrig.cpp:1056-1078`). Their runtime test value requested `item_index:1`, so the harness stopped before its later alternate-selection logic. Runtime-resolved combos now scan for the first enabled value different from the current value before rejecting the row (`indra/newview/aluiperfselftest.cpp:3340-3371`).

## Non-combo classifications

- `*_pitch`: **HARNESS**. Pixel-rounded arc geometry produced, for example, 36.8° for a 36° request; ±1° keyboard nudges then oscillated forever because the harness demanded exact 36°. Shipping dials map pointer angle and commit on down/hover/up (`indra/llui/alcompassdial.cpp:162-223`) and move by the declared increment in `handleKeyHere` (`:244-264`). The harness now establishes an exact adjacent pre-state before the baseline and sends keys directly to the target dial—never through `gViewerWindow`—until the unchanged exact oracle is met (`indra/newview/aluiperfselftest.cpp:3298-3316,3859-3873`).
- `cine_mirror`, `cine_key_shaft` pre-state: **HARNESS**. Preconditioning was a second real click during deferred layout. Pre-state is now set and committed before the measured baseline; the measured action remains a real mouse click (`indra/newview/aluiperfselftest.cpp:3838-3856`).
- `*_actor_only`: **PRODUCT GATE, HARNESS PRECONDITION**. The product intentionally disables these for an object-targeted rig and, except bounce, while Actor-only-all overrides them (`indra/newview/alpanelcinelightrig.cpp:2408-2449`). The harness already cleared Actor-only-all but did not clear the selected rig's object target. It now clears that public model state under the existing per-row rig snapshot/restore (`indra/newview/aluiperfselftest.cpp:1627-1675`).
- `cine_ratio`, `cine_ratio_lock`: **PRODUCT GATE, HARNESS MANIFEST**. They are advanced-driven controls and are disabled while effective Easy mode is active (`indra/newview/alpanelcinelightrig.cpp:2401-2404`). Their names missed the per-light regex, so the merged manifest lacked `CineLightRigEasyMode=false`; enrichment now includes both (`scripts/perf/functional_report.py:372-395`).
- `cine_fill_ev`: **HARNESS**. The run proved the click and commit: displayed `-3.5 -> -3.25`, setting `-3.0 -> -3.25`. The expected arrow step was incorrectly based on the stale setting baseline instead of the displayed spinner baseline. It now uses `mFunctionalControlBefore` (`indra/newview/aluiperfselftest.cpp:4079-4082`).
- `cine_bounce`, `cine_manual`, `cine_random_cycle`: **HARNESS**. `LLButton` only toggles/commits when release remains in the button (`indra/llui/llbutton.cpp:540-578`); the generic click helper alone advanced deferred layout between down/up. Ordinary clicks now keep one coordinate without a harness-inserted UI frame (`indra/newview/aluiperfselftest.cpp:3005-3028`). `cine_live_probe_refresh` is actually a five-item combo, not a toggle (`panel_dpage_light_cine_light_rig.xml:752-758`), and is fixed by the combo gesture change.

## Static prediction

All 42 run-135523 category-C combo failures should now deliver list mouse-up inside the chosen enabled row, invoke `onItemSelected`, fire the exercised combo's commit signal, and update their setting/provider oracle. Legacy `mode_combo`, kit `cine_track_mode`, and `preset_strip:rig_rim` should pass; gel/gobo rows should choose an enabled non-current runtime item. The named pitch, pre-state, parent-gate, fill-EV, and simple-toggle failures should also pass. Any remaining preset failure after a rerun would be new evidence against the statically complete provider/apply path above, not something hidden by this harness change.

# Run 124814 v2 triage

Scope: `run_functional_20261011_124814/functional.csv`, all 160 `FAIL` rows and each row's `observed` JSON. Verdicts were made from the captured dispatch/commit/state evidence and the cited shipping code before the harness changes. No product fix is included.

## Root causes and changes

- **H1 — captured drag was never delivered (HARNESS).** `LLViewerWindow::handleMouseMove()` only records the cursor (`llviewerwindow.cpp:1805`); captured hover is dispatched from `updateUI()` (`llviewerwindow.cpp:3935`, captured branch near 4205). `LLSlider` changes and commits from that captured hover (`llslider.cpp:247`). The harness now pumps `updateUI()` between down/move/up and drags every `LLSliderCtrl` (including the slider nested in an `ALKitRow`). Evidence: 52 slider rows reported exact down/up handlers, capture, zero commits, and unchanged values.
- **H2 — kit switch lacked an intervening frame (HARNESS).** The affected switches had exact real down/up handlers but zero commit (for example `cine_bounce`), whereas their setting binding was intact. The click path now pumps the shipping UI frame between down and up; safety preflight, captor/modal/menu checks, focus guards, and input reset are unchanged (`aluiperfselftest.cpp:2964`).
- **H3 — popup scroll state/return value/alternate selection (HARNESS).** Popup reshape can leave the list's internal scroll line stale; cells are computed from that state (`llscrolllistctrl.cpp:1881`, `setScrollPos` at 2949). The harness now always round-trips scroll position after open/reflow, re-reads the cell, accepts a list mouse-up only when an actual commit was witnessed (the list commits then returns its base result at `llscrolllistctrl.cpp:2065-2087`), and avoids selecting the current runtime item (`aluiperfselftest.cpp:3211`).
- **H4 — typed prerequisite comparison and missing mode gates (HARNESS).** JSON integers were compared to typed bool/F32 controls with strict LLSD equality. Comparison is now by declared control type (`aluiperfselftest.cpp:1567`). Generated prerequisites now put Easy callbacks in Easy mode, advanced light rows outside it, disable ratio-lock for Fill EV, clear Actor-only-all for child controls, and enable Fixture mode (`functional_report.py:373-397`). The shipping gates are at `alpanelcinelightrig.cpp:2371-2403`, `2418-2447`, and `2496-2505`; per-light option gates are declared in XUI at lines 237, 303, 377, and 443.
- **H5 — owner/oracle coverage (HARNESS).** Generated `owner` locations are exact binder evidence, so a witnessed synchronous commit now records that source owner when no registry symbol exists (`aluiperfselftest.cpp:3730`). Group toggles also verify the rig group bitmask (`aluiperfselftest.cpp:1720,1801`), and code-bound BG rows may use a consumer as their primary state oracle.
- **H6 — dial geometry (HARNESS).** The old fixed 0.7-radian drag could not represent the manifest target. The harness now uses the same compass/arc center, radius, and angle mapping as the control (`aluiperfselftest.cpp:3105`).
- **H7 — Fill consumer oracle (HARNESS, not product).** The selector writes the typed option value and `syncSelector()` shows only that option (`alkitcard.cpp:434-485,524-549`); Fill rows are bound to Fill settings (`panel_dpage_light_cine_light_rig.xml:303-376`). With ratio-lock, the panel intentionally displays `KeyEV - Ratio` in Fill EV (`alpanelcinelightrig.cpp:2496-2505`). The failed oracle compared that derived UI value to stored Fill EV; it now models the displayed value while retaining shaft/cone/hero checks (`aluiperfselftest.cpp:1826`).
- **D1 — legitimate login deferrals.** `cine_anchor` is a hidden backing picker, not the visible cast interaction; `cine_shadow_fixit` is explicitly `visible="false"` until needed (XUI line 545); `cine_rimq_enable_tag` appears only for `NO AVATAR TAG` (`alrigrimcontroller.cpp:334-404`). The gobo library needs inventory content. The night-tint swatch can be opened safely, but a real selection requires the modal picker's protected control-write path (`llcolorswatch.cpp:309-342`), so it is not faked by a direct widget commit. These rows become explicit `SKIP`, not weakened passes (`functional_report.py:399-408`; deferred visibility handling at `aluiperfselftest.cpp:3764`).

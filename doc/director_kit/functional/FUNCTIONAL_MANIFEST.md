## Action legend

- **RUN**: exercise at the login screen and assert `expect`. Rows with `known_gap` (UNWIRED) are counted separately; a failure there is the expected finding.
- **DEFER_INWORLD**: needs an in-world avatar, object, selection or running take. Also defer at runtime if the widget is disabled.
- **SKIP**: destructive (delete, clear, save, export, reset-all, file or path input). Reason is listed below.
- **EXPECT_MISSING**: the control is absent in that version; the test asserts absence.
- **NO_EXERCISE**: widget type has no generic exercise (viewport, texture picker, custom).

## Caveats

- Deferral and destructive classification is name and label based (token rules in the script). The runtime must also defer any widget that is disabled at login.
- Combos and radio groups without XUI items (kit combos) carry `item_index: 1` with `resolve: runtime`; the runner reads the item list and picks the second value.
- Setting min, max and increment come from the XUI element only. Settings XML carries no range.
- v2 launcher stubs (`v2_launcher_redirect`) host their controls in the v1 owner floater that they open; test them through the launcher.
- XUI lookup warnings: 0 (widgets whose CSV name has no named XUI element, usually unnamed `check_box`/`slider` rows, or settings-only names). The setting still comes from the CSV; the full list is in `meta.warnings` of the JSON.
- Coverage check: every interactive legacy CSV row yields one entry per applicable version; every converted v2 page is instead inventoried from its generated `panel_dpage_*.xml` body rows and card/option header switches.

## Director rule checks (runtime, `-Functional -DirectorV2` and `-InWorld`)

These run after the manifest rows inside the same session. They are viewer-local UI checks (real clicks on shell chrome, navigation and help APIs, widget-tree reads) and never press a control that sends, saves, deletes or opens a file picker. Each emits PASS/FAIL/WARN rows (`kind=rule`) into `functional.csv`; any FAIL fails the run.

### R1_REACHABILITY - Every page and link is reachable through the real navigation code

- rail click then tab click (gear click for Settings) selects the page: right group, tab toggled, visible in chain, non-zero size, inside the floater
- ALKitShell::navigateTo(page key) selects the same page from another page
- every link row and card link click lands on its target page (widget visible and highlighted)
- the generated registry matches the live shell (pages, rail groups)

### R2_POPOVERS - Every shell popover opens correctly and closes both ways

- anchor click opens exactly one popover of the expected name
- visible, front-most child of the shell at its centre, inside the shell rect, taller than the 10 px stand-in, buttons inside its rect
- a second anchor click closes it; Esc closes it
- covers ACTION options, legend, hotkeys, scene menu, cast, search results, and per page Reset and Who popovers

### R3_LABEL_FIT - No visible label is clipped

- font text width against the drawn box for kit row labels, page-bar master labels, who chips, tab and rail labels, button labels, transport and popover labels
- clipped without elision = FAIL; elided = WARN listing the label
- every section chip of every page is walked so rows behind the active chip are measured

### R4_RAW_NAMES - No internal id is ever shown to the user

- help column text for every row, card and page (help column update called per item)

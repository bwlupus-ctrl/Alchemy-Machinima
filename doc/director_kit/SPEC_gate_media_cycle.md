## Contract

Extend the existing Gate to ARM any mixture of existing Camera Feed, MEDIA_URL and MEDIA_FACE slots, within the existing eight-slot/eight-arm limits. Surface Lens restrictions remain. Arming stores a reference; it creates no camera, player, download or playback intent.

- **Transition:** Cut (default, preserving existing scenes), or Crossfade; fade length defaults to **0.5 s**, finite range **0.1–3 s**. **If crossfade is over budget: Cut instead (DEFAULT) / Fade anyway / Hold until it fits**. One monotonic-time blend drives every Gate display, projector/cookie and Gate audio.
- **Auto-cycle:** enabled armed order, wrapping and skipping unavailable feeds. **Private videos: Use interval / Play to end**, default Use interval. Cameras and borrowed faces use `mIntervalSeconds` (existing 8 s default, 0.5–120 s). For MEDIA_URL, Play to end overrides authored Loop, including unknown duration; known-length fades start at `max(0, D - fade - E)` (carried estimator error bound `E`) and unknown-length fades start from held EOF pixels.
- **Before every take:** only a ready feed can enter Program. MEDIA_URL checks/admission, complete HTTP download, muted load and tokened seek/decode precede commitment; Live receives a final freshness check. Cameras require a produced frame and destination preflight; MEDIA_FACE requires an accepted destination-sized copy, with image demand only. Manual Preview uses the same readiness path; early Take queues one request and leaves Program intact.
- **MEDIA_URL On cut:** Restart / Resume / **Live (default)**. Off-air private players pause immediately, release after **about 60 s** idle or earlier under pressure with bookmark/status retained. Live simulates elapsed off-air transport without decoding; unknown length uses Restart with visible status, never Resume semantics.
- **Audio:** private Program follows slot Volume/global policy; warm/off-air gain is zero. Crossfade ramps private gains; Cut attempts a short plugin-timer de-click ramp, falling back to a tokened gain step without blocking the Cut. Slice-2b admission/clamps remain authoritative. Borrowed-face audio stays once at the original prim and is never controlled by Gate.
- **Continuity:** retain accepted outgoing pixels, cookie and volumetric ownership throughout warm-up and transition. An admitted same-input loop is a transport operation. No generated BLACK/no-signal frame at a cut.
- **Scenes:** save transition, duration, over-budget choice, private-video dwell and URL On cut. Camera Gates restore active as today. Restored private URLs remain syntax-only/stopped; one Gate **Play videos** click authorizes all armed private videos for this session, which then enter the normal cycle without disturbing the camera on air. Arming/restoring never authorizes private I/O. Borrowed faces retain their existing policy-gated consumption contract.

The user's external hardware recorder captures the live output. Stable presented frame rate and hitch-free cuts are release requirements, not deferred recording polish. This adds no recorder, offline playback engine, timeline, history or new media admission system.

This plan supersedes only the camera-only Gate exclusions and MEDIA_URL Gate transport behavior in `SPEC_media_projector.md`, with its **v8.2 creation-time repeat amendment**; retain its borrowed-face boundary, downloader/cache, file safety, policy, provenance, lifetime, shader-state and no-history requirements. Carry forward `DIAG_media_loop_glitch.md` with the measured same-input prerequisite below.

## Gate state machine

Implement a pure reducer in `llprismgate.{h,cpp}`: clock + config + bounded source/readiness events in; state + warm/pause/seek/commit/mute/release actions out. Registry executes actions asynchronously. The reducer is the **single Gate timing owner in every kill-switch mode**; remove Gate timing from `ALDirectorSwitcherModel::Controller`, leaving the separate Director switcher unchanged. Stable handles/request generations, not row indices, identify transitions.

| State | Behavior and exit |
| --- | --- |
| INACTIVE | No Gate playback/warm intent. Explicit activation grants the defined session scope and enters WARMING for the chosen first arm; restored active state keeps private arms waiting for Play videos. Retain existing output until a first valid Program publication. |
| ON_AIR | Serve Program; select one successor (Auto order or Manual Preview). Begin URL input/admission preparation immediately after settling; camera/face image readiness has independent destination-sized demand. |
| WARMING | Program continues. URL: Checking → Downloading → Admitting muted → Seeking → accepted frame/preflight. Camera/face use image readiness. A due boundary/Take queues one request; bounded failure skips this pass. |
| READY | Hold prepared URL paused/muted at the predicted commit target; keep camera/face image demand. Re-seek only for prediction movement beyond tolerance; bounded resume/time/frame and output revalidation precede Cut/CROSSFADING. |
| CROSSFADING | Two fixed identities; `a = clamp((now - start)/duration, 0, 1)`. No third warm candidate. At `a=1`, finish routing and pause/bookmark outgoing; wait for retirement acknowledgement before new decoder work. |
| HOLDING | No usable successor: retain valid Program/EOF pixels and reason, with no retry spin. Resume on relevant completion/readiness/budget events, edits or explicit activation/Play. |

Generic Playing, dimensions, old `mHasOutput` or immediate seek-command acknowledgement do not establish readiness. Keep old publication separate. Transport tokens reject stale requests/completions; **they do not prove decoded-frame PTS or a decoder flush**. Promote incoming demand before commands; observe actual resume/time progression and a new completed frame before commitment, with the terminal/still exception below. ### On cut position math

For MEDIA_URL, when it ceases contributing, mute/pause and obtain **estimated media time** `p` and mapped monotonic pause time `t_off`, retaining subsecond precision under the measured error bound below. Idle release (about 60 s, or earlier pressure eviction with visible status) preserves this bookmark. Compute the desired first-contributing position for predicted commit time `t_commit`, not early warm time:

```
Restart: target = 0
Resume:  target = p
Live:    q = p + max(0, t_commit - t_off)
         target = q mod D              if Loop and finite D > 0
         target = clamp(q, 0, max(0, D - frame_duration))  if not Loop
         target = 0                    if duration is unknown (Restart)
```

No bookmark means target zero for this take; the first acknowledged off-air pause establishes `p/t_off`. Reject nonfinite inputs. For unknown duration, latch Restart for this take and show exactly **`Live needs a known length - restarting`**; never substitute Resume, including after idle release. If length becomes known later, use it on the next take. Known-length nonseekable Live reports `Live needs seek support` when a nonzero seek is required; nonseekable Restart may start normally at zero. Resume may retain a paused nonseekable player, but after release report/skip if its bookmark cannot be restored. Invalidate bookmarks on real source replacement/Stop, not idle release; On cut edits invalidate pending preparation. No persisted off-air wall clock.

**Time source/tolerance:** plugin-side `libvlc_media_player_get_time` step-edge capture, polled about every **10 ms** independently of the 20/40 ms media tick, timestamps old/new values with `steady_clock`. Interpolate between captured step edges at the observed playback rate; map to viewer monotonic time using receipt timestamps. About 250 ms value steps are not 250 ms polling latency: bracket edges and calibrate the value/edge phase in slice 1. Reset on seek, pause/resume, wrap, rate change or discontinuity; never extrapolate indefinitely (invalidate after 500 ms without a playing step). Carry estimate/sample age/error with transport replies. Acceptance target is **100 ms**, maximum **150 ms** total commit-position error, including clock mapping/interpolation/resume; there is **no frame-PTS proof**. Prove the bound with visible numbered/timecoded fixtures in slice 1, including VFR/B-frames, load and long READY dwell; failure blocks enablement.

Interval predicts the next boundary; known-length Play-to-end predicts early-biased end for Cut and early-biased end minus fade for Crossfade. **Seek EARLY**, as soon as admission and a prediction are available, to the position wanted at commit; decode and park paused in READY. Remove the 200 ms final-seek window. Let `E` be the carried measured conservative estimator error bound (expected ≈50 ms). Re-seek only if the prediction's target moves by **more than `T = 150 ms - E`** (expected ≈100 ms; circular distance for Loop), including late downloads/early Take; at most one corrective seek per attempt under existing deadlines. Unknown EOF/Manual use the request time and may remain Take pending while preparing. Resume with measured lead and account for its advancement once; compare the estimate with the target at actual commit, require a new accepted frame after observed convergence/resume and completed-frame age ≤max(one source-frame period, 150 ms). The commit check allows uncorrected drift `d ≤ T` relative to the prepared target plus uncertainty `E`, with resume advancement accounted once: within-threshold drift must never cause a spurious skip, while total `d + E ≤150 ms`. If `E ≥150 ms`, timing qualification fails. If total error exceeds 150 ms or the clock is invalid, keep Program and fail/skip under the existing cap. No continuously seeking READY loop.

Restart/Resume preserve the requested start within the same 150 ms timing tolerance: prime/park at target, then time resume/commit on a new frame. Where the decoder cannot meet it, defer and report measured resume latency; do not silently consume the beginning while muted.

For non-loop Live exhaustion, never seek exactly `D`: use `D - one frame` from reported frame rate (fallback 100 ms tail lead), then bounded tail decode through matching EOF and its completed final image. No inferred frame PTS or time-only terminal-frame proof. Retain that accepted image; Play-to-end may advance after publication. New-motion checks accept this terminal-frame case without waiting for impossible motion.

## Outputs, audio and bounded cost

Freeze a **participating destination set** per transition: currently enabled/online Gate subscriptions whose shader/sampler/target/framing preflight succeeds for both feeds at destination size.

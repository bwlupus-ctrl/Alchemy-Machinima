## Decision and scope

> **USER RULE (10/17, binding, revised): the Video source accepts VIDEO FILES ONLY**, from http/https links **or local files**. The user is fine with local media, but nothing that isn't video may reach the player.
> - **Sources:**
>   - `http`/`https` URLs to a video file;
>   - **local files** chosen with a **Browse…** button through the existing file picker (LLFilePicker, video filter), and a typed `file:` path or absolute local path.
>   - **Refused:** UNC/network paths (`\\server\share`, `file://server/...`), which on Windows can leak NTLM credentials over SMB, plus other schemes (`rtsp`/`rtmp`/`mms`/data/...) and relative paths.
> - **Gate 1, extension:** the path, ignoring query and fragment, must end in `.mp4`, `.m4v`, `.mov`, `.webm` or `.mkv`, case-insensitive. Otherwise it is refused before any I/O.
> - **Gate 2, real container (header sniff before VLC sees it):**
>   - **Local:** read the first bytes. MP4/M4V/MOV must contain an ISO-BMFF `ftyp` box (or a leading `moov`/`mdat`/`wide`/`free` box for old QuickTime). WebM/MKV must start with the EBML magic `1A 45 DF A3`. Anything else is refused ("This file isn't a video"), even with a video extension.
>   - **http(s), under option A below:** download the complete final 200 response, with `video/*` or `application/octet-stream`, excluding playlist types; sniff the exact completed cache file before VLC sees it. Section 2 defines mediated redirects and streaming limits. No HEAD/Range probe or HTML fallback.
> - **Gate 3, after load:** LibVLC must confirm at least one video track under the current load token and a bounded deadline; length is never part of the verdict. Incomplete track metadata stays **PENDING, MUTED** with tokened rechecks; an early audio-only track list is not a terminal verdict. Unknown or zero length means non-seekable (seek/scrub disabled), with Loop restarting on admitted EndReached as usual. Until admission audio gain is zero and no image is published. Conclusive failure or deadline stops/releases the player and shows "This file isn't a video". Audio-only never becomes audible.
> - **Local-file lifetime:**
>   - Scenes save the absolute path; it only works on this PC.
>   - A missing file shows "File not found" and the slot stays stopped.
>   - The path is never uploaded or sent anywhere.
> - **Out of scope:** streams (HLS/DASH/RTSP/live) and web pages.
> - **Validation runs** on Play and Browse; scene restore is **SYNTAX-ONLY**, with no network request or filesystem call (including stat/existence/canonical-target checks). Restore cues, never auto-plays. A refused entry stays in the field so it can be corrected.
>
> **USER DECISION (10/17, binding): http(s) = DOWNLOAD, THEN PLAY (option A).** It replaces any design in which VLC fetches from the network.
> - **Download:** the viewer downloads the whole file with its own HTTP stack into a private media cache, under the user cache directory, not the repo. VLC **never touches the network**; it only plays the validated local cache file.
> - **Same gates as local files, on the exact downloaded bytes:** extension, header sniff, then the VLC video-track verdict. This removes the time-of-check/time-of-use gap and the redirect bypass.
> - **Redirects:** mediate them, with no blind auto-follow. Each hop's scheme and host are checked (http/https only, never a file: or UNC target); the final hop's path extension is re-checked.
> - **Size cap:** new setting `VCamMediaDownloadMaxMB`, default 2048 (2 GB). Abort as soon as Content-Length or the received bytes exceed it ("File too large"). The body is streamed to disk in chunks, never buffered whole in RAM. If LLCore can't stream or cap, add that seam or use a dedicated downloader.
> - **Status:** "Downloading 45%", then the normal states. Playback starts after the download and validation complete. Stop or Remove cancels the download and deletes the partial file.
> - **Cache:** keyed by URL. Repeat plays are instant. Bounded total size with LRU eviction (new setting `VCamMediaCacheMaxMB`, default 8192). A Clear action is available.
> - **Scene restore** stays syntax-only: it never downloads automatically; Play does.
> - **Loop (Opus P2):** apply input-repeat / looping only AFTER a positive video-track admission, e.g. restart on EndReached. It is never set at media creation.

> **Binding user decisions:** “I thought that the URL would be the VLC method”. The mockup's **Video URL** source kind has a **Video** field accepting an http(s) video-file link or local path, plus **Browse…** and a private, slot-owned LibVLC player. **Prim face media** remains the second kind, borrowing an existing LibVLC face. No streams or CEF/web pages. **Loop defaults ON**; Volume defaults to zero. Both use existing VCam outputs. VCam has **no undo/history**.

A media slot copies newly completed frames from its private player or chosen face's LibVLC texture into its retained slot output image instead of rendering a camera. It can drive prim display faces and projector lights, including existing auto-volumetric behavior, with several outputs at once. It appears in the existing VCam monitor previews and uses the existing fit, output looks, no-signal, rate/budget and scene workflows. No dummy camera or separate media-projector registry/editor is required.

Out of scope: CEF/web sources, website/player-page URLs and shared playback synchronization.

Flow: http(s) link -> syntax gate -> viewer download into private cache -> exact-file container gate -> local-only private LibVLC admission; typed/browsed local file -> syntax/local-safety/container gates -> the same admission. Either private player **or** chosen prim face -> validated existing LibVLC impl -> completed viewer media texture -> existing slot GPU copy -> display/preview compositors and prepared projector cookies -> prim faces, surface lighting and volumetrics.

This is viewer-local. No outbound simulator/object/media/navigation messages, asset upload or light texture UUID change is allowed. Other viewers see the ordinary face/light state and never see/hear the private player. Only the viewer downloader contacts HTTP(S) hosts; private VLC receives local files only and never touches the network. Local paths/content are never uploaded or sent anywhere. Interacting with a borrowed face's original player can still have the usual shared-media effects.

Reuse existing OBJECT and RIG_LIGHT projector destinations and their arbitration. `EProjectorTarget::VIRTUAL` exists (`indra/newview/llprismlens.h:107`), but current emitter resolution supports object/rig lights (`indra/newview/llprismlens.cpp:5824`); this feature adds no emitter type. No CPU readback or auxiliary camera capture. Borrowed faces are never navigated/resized/reconfigured; their bootstrap remains policy-gated. Private creation/navigation is confined to explicit Play below.

## 2. Private video-file and borrowed-face sources

### Primary source: Video URL / local file (slice 2b)

New media slots default to **Video URL**, empty and stopped. The **Video** field accepts absolute `http://`/`https://` file URLs, absolute native local paths (drive-qualified on Windows, `/...` on macOS/Linux) and local `file:` URIs. Reject relative/drive-relative paths, other schemes, streams/manifests and web pages. Typing/commit, kind selection, preview demand, scene restore and Freeze/Resume perform **syntax-only validation, no network or filesystem I/O, navigation or playback**. A valid replacement tears down the old private player, preserves slot/output identity and cues the new descriptor. Invalid text remains editable without replacing the committed descriptor or enabling Play for that text.

**Browse…** uses `LLFilePickerReplyThread::startPicker`, as in `alpaneldanceball.cpp:2079`, never blocking `getOpenFile`. Add `FFLOAD_VIDEO` without renumbering existing filters, with `.mp4/.mov/.m4v/.webm/.mkv` filters in native Windows, native macOS and SDL/Linux backends. Picked paths pass the same syntax, local-safety and container gates as typed paths; the picker filter is no security gate. Browse may preflight a picked file but only cues it, never creates/plays a plugin. Cancel/stale panel/slot generation leaves the descriptor intact. Play repeats local checks; a Browse result is not permanent admission.

**Local safety, before opening content (O3):** canonicalize spelling lexically first, including slash variants and one decoding of `file:` escapes. Reject `\\server`, `//server`, `\\?\UNC\`, all `\\.\`/`\\?\` device paths, `file://host/` (any nonempty authority) and `file:////host` **before any filesystem call**. On explicit Browse/Play only, reject mapped drives with `GetDriveTypeW == DRIVE_REMOTE` before stat/open. Inspect each local reparse point/junction/symlink without following it; reject a remote target before accessing it, and fail closed if locality cannot be established. Apply equivalent remote-mount checks on macOS/Linux. Do not resolve first and reject after an SMB access; retain the validated file handle or enforce the same no-follow/locality checks at playback open so a changed link cannot bypass refusal. Existence/header reads and potentially blocking drive/target checks use the **detached I/O isolation below, never the General ThreadPool/WorkQueue, LLCoros or main**. Shared/crafted scenes never stat anything on restore.

**Three gates (O1/O2/C4):**

1. **Syntax/extension, before I/O:** case-insensitive `.mp4`, `.mov`, `.m4v`, `.webm` or `.mkv`. For HTTP(S), parse the URL path ignoring query/fragment; for a native file, `#`, `%` and other legal filename characters are literal. Local-path parsing precedes generic URI parsing: `C:\...` otherwise becomes scheme `c` (`LLURI` splits at the colon). Apply the UNC/device refusal above first. Empty is a valid cue but cannot Play.
2. **Container before VLC:** the isolated local worker checks existence (missing => **"File not found"**) and reads the first 64 bytes. MP4/M4V/MOV need a structurally plausible ISO-BMFF `ftyp` box or leading old-QuickTime `moov`/`mdat`/`wide`/`free`; WebM/MKV need leading EBML `1A 45 DF A3`. Reject malformed/truncated/nonmatching headers with **"This file isn't a video"**. HTTP(S) first completes the capped download below, then runs this same sniff and side-file check on that exact cache file, retaining its immutable cache lease through playback; no probe/refetch gap. The final response must be **200**, nonempty and complete; unsolicited 206, 204 and other statuses fail, reporting HTTP failures with their status. Accept only `video/*` or `application/octet-stream`, excluding playlist/manifest MIME types; missing/unknown, HTML and audio MIME fail. **Refuse `application/mp4` and `binary/octet-stream`**. No missing-type rewrite to HTML. Headers, MIME and extension are not video proof: renamed M4A and HEIC can carry `ftyp` and must fail gate 3.
3. **Tokened video admission (Codex P1 / Opus P1):** for **local and cached files only**, pin per-media **`:demux=mp4`** for MP4/M4V/MOV or **`:demux=mkv`** for WebM/MKV, before playback; no playlist/other-demux fallback. Admission starts **PENDING, MUTED**. VLC 3.0.23 emits ESAdded per track: an audio-first notification or empty/incomplete track list is not a rejection. On the normal plugin message thread, re-query `libvlc_media_tracks_get`/`libvlc_track_video` on Playing, ESAdded and media metadata/parse changes, plus a bounded **100 ms tick** while pending; release every track array. Admit as soon as current metadata confirms a video track, **regardless of length**. Unknown/zero length is non-seekable: disable seek/scrub, but retain admitted EndReached Loop. LengthChanged updates transport capability only, never admission. Duration-less WebM/MKV (e.g. MediaRecorder/interrupted OBS files) can be valid; HTTP clean EOF, byte cap and transfer deadlines already exclude live transfer playback. Remain pending only while video-track proof is incomplete; reject only conclusive completed-enumeration/no-video or input failure, EndReached/EncounteredError before admission, or the **10-second monotonic deadline from local player opening**, never reset by notifications. Playing/ESAdded alone never proves enumeration complete; if completion cannot be proved, defer a no-video verdict to the deadline. Decoder event callbacks only enqueue tokened changes for the normal message thread. `reportVideoSize()` is geometry/SAR only. Rechecks/verdicts carry immutable player/load token; viewer also checks slot generation/Play token. Before a positive current verdict, publish no frames and clamp effective gain to **0 in both viewer and plugin**, regardless of user Volume/unmute, global gain updates or rebuilds (`mRequestedVolume` starts at 1.0; plugin `mCurVolume` alone is insufficient). A terminal failure stops/releases, revokes demand/readiness and shows **"This file isn't a video"**; Loop cannot retry it. Stale messages are ignored and cannot change the current player's state or gain.

**Downloader choice and exact seams:** use a **dedicated detached downloader thread with the viewer's bundled libcurl**, not LLCore requests. Opus verified `HttpOpRequest::writeCallback` appends to `BufferArray` without limit (`indra/llcorehttp/_httpoprequest.cpp:804-816`), `HttpOptions` has no body cap (`httpoptions.h:74-181`), and `HttpCoroutineAdapter` buffers the reply (`indra/llmessage/llcorehttputil.cpp`). Adding a sink/cap/redirect seam would still put potentially blocked disk writes on shared HTTP infrastructure. A private worker confines that risk without changing general HTTP behavior. Add proposed `indra/newview/alvcammediafileio.{h,cpp}` for `startPreflight`, `startDownload`, cancellation and cache I/O; main-thread `llprismlens` runtime state owns request subscriptions/cache leases and consumes results before creating `LLViewerMediaImpl`. Register the helper in `newview/CMakeLists.txt`; settings belong in `newview/app_settings/settings.xml`.

**Whole-file transfer and redirects:** each job owns a raw `curl_easy_init` handle (not `LLHttp::createEasyHandle`'s auto-follow template). Set **`CURLOPT_NOSIGNAL=1` on every job handle** (including a fresh handle for a later hop; raw handles do not inherit the template setting at `httpcommon.cpp:284`), `CURLOPT_FOLLOWLOCATION=0`, HTTP/HTTPS-only protocols, TLS peer/host verification and copied viewer proxy/CA configuration. Use header, write and progress callbacks (`CURLOPT_HEADERFUNCTION`, `CURLOPT_WRITEFUNCTION`, `CURLOPT_XFERINFOFUNCTION`) on that thread. Issue a whole-file GET, no HEAD/Range probe, resume or automatic retry. Apply the scheme/host rules to the initial URL too. Follow only 301/302/303/307/308 with a valid Location; resolve relative Location values and approve each hop **before requesting it**: only http/https, valid nonempty host/port, no userinfo, control characters, backslash/UNC ambiguity or file target; at most **5 redirects**. Check the final URL's extension again before accepting body bytes; intermediate CDN paths need not have an extension. Never forward credentials/cookies across hosts. Refuse unapproved hops without contacting their destination. Validate final status/MIME before writing its body; stop redirect/error responses after their headers without consuming their bodies. VLC receives no HTTP(S) URL or request headers. Do not use a `libvlc_media_new_callbacks` reader; private VLC has no network access and performs no download.

Stream chunks of at most **64 KiB** directly to the private partial file, with checked 64-bit counters. `VCamMediaDownloadMaxMB` defaults **2048**; MB here is 1024*1024 bytes. Reject an excessive Content-Length before its body and abort **before writing a chunk that would exceed the cap**, including chunked/unknown or false lengths. Request identity content encoding and reject unexpected content encodings so size/sniff apply to the stored bytes. Require clean EOF and any declared length to match; truncated/empty transfers fail. Report **"File too large"** for the cap. Bound connect to **30 s**, no-progress transfer to **30 s**, total transfer including hops to **30 min**; cancellation is checked by every callback. Show **"Downloading N%"** for a trustworthy positive total (100 only at completion); otherwise **"Downloading..."** with received bytes separately. Only after completion and file preflight may a current Play advance to local VLC admission.

**I/O ownership and shutdown isolation (Codex P1):** preflight, cache scan/read/write/flush/rename/delete and download I/O run on dedicated **detached, non-joined** jobs, never a pool the viewer closes. `threadpool.cpp:187` calls `close()`, `:213` joins workers synchronously, and `llappviewer.cpp:2251` closes General: merely moving filesystem calls to its WorkQueue still hangs quit. Each job owns its paths, file/HTTP/native-thread handles, immutable policy snapshot, cancellation atomics and a self-contained result mailbox; no slot/impl/UI pointer or viewer singleton is captured. Main polls bounded progress/results with slot generation, Browse/Play token, job ID and cache epoch; detach a retiring slot's subscription, close an orphaned job's mailbox, and close all mailboxes at quit. Other subscribers retain a shared job's results; stale results are discarded. Hold no main-needed lock across I/O. Limit outstanding jobs to **8 total, including cancelled but still blocked jobs**; refuse new work when exhausted rather than growing detached threads.

Give each filesystem operation a **5 s deadline**. On Windows prefer overlapped I/O with deadline + `CancelIoEx`; for synchronous calls where supported request **`CancelSynchronousIo` on the worker's native thread handle**. A deadline/cancel makes the request terminal on main without waiting for the syscall to return; unsupported/uncancellable calls remain isolated. Stop and disable never join, wait on a future, close a busy worker handle synchronously or drain its queue. Workers clean up when the OS call returns; they cannot publish/restart after cancellation. Retain only job-owned resources until then. Workers use copied TLS/proxy data and no viewer-dependent callbacks/logging. Add an active-download lease at **`LLHttp::cleanup()` (`indra/llcorehttp/httpcommon.cpp:347-350`, called by `llappviewer.cpp:2354`)** so global curl/TLS cleanup is skipped while any detached transfer remains; never tear shared library state down under it.

**Process lifetime (v8, both parts required):** at the **start of `LLAppViewer::init()` (`llappviewer.cpp:865`), before `setupErrorHandling`, configuration or any curl/TLS use**, call `OPENSSL_init_crypto(OPENSSL_INIT_NO_ATEXIT, nullptr)` and check success. This precedes `mAppCoreHttp.init()` (`:935`) -> `LLAppCoreHttp::init()` (`llappcorehttp.cpp:153`) -> `LLHttp::initialize()` / `curl_global_init` (`httpcommon.cpp:335-340`); no earlier TLS initialization may precede this call. OpenSSL must never register its atexit cleanup ([OpenSSL initialization](https://docs.openssl.org/3.0/man3/OPENSSL_init_crypto/)). At entry to **`LLAppViewer::cleanup()` (`:1897`)**, stop accepting jobs, cancel **all** outstanding jobs (including already-cancelled workers), invalidate/close mailboxes and start one **2 s monotonic drain budget**. Poll completion without joining or doing job I/O on main; no worker may extend this budget. At the persistence-complete tail of that function, **at the existing fast-exit seam (`:2384-2404`), before returning/destruction**, if **any job** remains after the bounded drain, flush settings/logs, remove normal-exit markers, then call **`_exit(0)`** (or Windows **`TerminateProcess(GetCurrentProcess(), 0)`**) instead of returning through CRT/static teardown. This override is mandatory even with **`BDMergeFastExit=0`**. Retain job state and the cache lock until process death on this path; no shared-state destruction beneath a surviving worker. A fully drained shutdown may follow the normal path. ## 9. Recording limits and open questions

External hardware capture records display/audio in real time; it does not synchronize download completion, VLC decode, media upload, VCam publication, viewer presentation and recorder clocks. Expect repeated/dropped frames and variable start/latency. Image rate is bounded by completed source frames, slot entitlement and viewer renders. Audio can continue while images stall. A saved scene, fixed viewer FPS or paused simulation is not frame-exact media replay.

For a repeatable take, use a stable seekable video file, explicitly Play/verify/Pause the private source (or cue through the original face controls), then use a visible flash + audible clap/timecode. Keep the viewer active and measure offset/drift at both ends of a long recording; unmute private Volume deliberately. Capture the viewer's actual audio device without duplicate monitoring. Diagnostics include HTTP/local/face kind, desired transport, download bytes/total/cache hit/reservation/eviction/cancel/error, gate/PENDING/admission/deadline/budget state, epoch/Play/load token, rejected stale frames, resolved plugin, geometry/SAR/fallback aspect, completed/slot/cookie serials, failures/retries, cadence and image age. Frame-locked/offline decoding and HDR/wide-gamut conversion remain outside scope.

**Open questions (two; no safety gate is deferred):**

1. Which OS/GPU, VLC source, viewer/recorder FPS and audio-device route define the acceptance setup? Include Duration-less WebM locally/cached, a controlled HTTP/redirect host, two viewers sharing a cache, supported/unsupported FileDispositionInfoEx, held TLS-read/disk-I/O quit with BDMergeFastExit=0, main/worker uploads and a long flash/clap recording.
2. Is the existing 2 NORMAL media-instance default sufficient for the expected mix of distinct simultaneous clips? Preserve it for v1 and measure contention before any separately approved scheduler/limit change.

# Media source slots in VCam — v4

Technical plan, 2026-10-17. Spec revision v4 for the first implementation (v1 feature scope). In Round 3 both reviewers confirmed all six v2 findings resolved; this revision incorporates four new P1s checked against code, including the simpler target and mapping-lifetime designs. Source references describe the current working tree; new types, fields, messages and behavior below are proposed. `CLAUDE.md` was read first. Only this document changes: no code, build, commit or push.

## Decision and scope

> **Binding user decisions:** v1 borrows the image from an existing Media-on-a-Prim face whose active player is **LibVLC**, for direct video/stream URLs. Add an explicit VCam **MEDIA SLOT** type, so it can be patched into the existing outputs. VCam has **no undo/history**.

A media slot copies newly completed frames from the chosen face's LibVLC texture into its retained slot output image instead of rendering a camera. It can drive prim display faces and projector lights, including existing auto-volumetric behavior, with several outputs at once. It appears in the existing VCam monitor previews and uses the existing fit, output looks, no-signal, rate/budget and scene workflows. No dummy camera or separate media-projector registry/editor is required.

Out of scope: CEF/web sources and a private URL player.

Flow: chosen prim face -> validated existing LibVLC impl -> completed viewer media texture -> GPU copy into VCam media slot output -> existing display/preview compositors and prepared projector cookies -> prim faces, surface lighting and volumetrics.

This is viewer-local. Subscribing an image sends no object/media update, uploads no asset and changes no light texture UUID. Other viewers see the ordinary face/light state; local point-light promotion and rig emitters keep their existing local behavior. Interacting with the original player can still have the usual shared-media effects.

Reuse existing OBJECT and RIG_LIGHT projector destinations and their arbitration. `EProjectorTarget::VIRTUAL` exists (`indra/newview/llprismlens.h:107`), but current emitter resolution supports object/rig lights (`indra/newview/llprismlens.cpp:5824`); this feature adds no emitter type. No CPU readback, auxiliary camera capture, independently created player, source navigation or source resizing is part of the handoff. Bootstrap demand can let the ordinary media lifecycle create the selected face impl's LibVLC source under its existing playback policy.

## 1. Explicit slot kind and existing output contract

**Proposed:** introduce a source-slot kind such as `ESourceSlotKind::{CAMERA, MEDIA_FACE}` at the VCam producer level. A CAMERA payload retains the existing `ECaptureMode::{SURFACE_LENS, CAMERA_FEED}` and camera data; a MEDIA_FACE payload contains object UUID, TE index and source-aspect selection. Common slot data owns stable handle/generation, label, rate, retained image metadata, runtime status and output bindings. Camera-only payload/state is absent or inaccessible for MEDIA_FACE, never a zero-filled virtual camera.

Generalize the current `CaptureDefinition` / `PrismInstance`, registry snapshots and binding source handles into this tagged producer contract (`indra/newview/llprismlens.h:729`, `:770`, `:926`, `:973`; `indra/newview/llprismlens.cpp:1846`). Existing handle/serialized names may remain as compatibility aliases, but every accessor must distinguish a source slot from an actual camera capture. The media descriptor belongs to the slot, not to each projector: all its outputs share one copied frame.

**Why this answers the v1 objection:** rejecting “a third `ECaptureMode` pretending to be a camera” was correct for an untagged extension. Adding such a mode would fall through camera transforms, HDR/exposure, gate and capture-only persistence checks. This design adds a distinct producer kind, branches before camera processing and shares only the retained-image/output contract. It deliberately audits those assumptions instead of expecting a new enum value to make them safe.

| Shared slot/output behavior | MEDIA_FACE behavior |
| --- | --- |
| Capacity, identity and routing | Share the existing **8 total source slots**, **16 display bindings** and **8 projector bindings** (`llprismlens.h:37-39`), without raising caps. One slot can feed multiple faces and lights together. Source identity and destination identity remain independent. |
| Retained image | Copy once per accepted new frame into the slot's pipeline-owned output image; displays, previews and projector preparation sample that retained image. No consumer samples a changing plugin GL name during lighting. |
| Fit and looks | Keep per-output FIT/FILL/STRETCH, anchor, flip/rotation, TV/screen effects, projector film/TV looks and lamp controls. Use the media source aspect and explicit SDR signal metadata; skip camera optics/exposure. Animated output effects can update without a new source frame. |
| No signal | Keep existing display behavior and projector OWN_COOKIE/BLACK/WHITE choices. A same-source late upload keeps its last accepted image; source/policy loss invalidates it. Frozen consumption retains a valid image only while the source remains valid and permitted. |
| Previews and scenes | Normal VCam monitor tiles, raw/output views, selection, labels, status and scene round-trip apply to media slots. Preview-only demand can keep a slot updating with no connected output. |

Camera-only work is skipped for media: world render pass/scratch render pack, camera object/transform, FOV/throw-follow-camera, exposure and auto-exposure, optics/depth/DOF, gate arming/prewarm/cuts, bone POV and camera map icons/frusta. There is no fake camera icon at the source prim. Media cannot be armed into the camera gate or inherit a gate subscription. Normal fixed slot routing remains available.

## 2. Borrowing a face: plugin identity, lifetime and policy

### Resolve the actual player

Pick a prim face, validate a live `LLVOVolume`, TE bounds and its `LLMediaEntry`, then obtain the associated impl through `LLVOVolume::getMediaImpl(te)` (`indra/newview/llvovolume.cpp:3197`). Object UUID + TE is the authored identity. Media ID is a current validation aid, not a substitute for proving that the selected face still owns the impl. Never call `newMediaImpl()` with that media ID: it can unload/reconfigure the existing player (`indra/newview/llviewermedia.cpp:315`).

Record the **resolved plugin basename on the impl at successful source creation**, carrying the selected name out of `newSourceFromMediaType()` (`llviewermedia.cpp:1834`, `:1841`) after platform substitution and successful creation/assignment. Clear it in `destroyMediaSource()` (`:1791`) and on creation failure; invalidate image/aspect readiness and advance the source epoch. A live media source is accepted only with **non-null source and resolved name exactly `media_plugin_libvlc`**.

Re-check this every frame, even when object UUID, media ID and impl pointer are unchanged: `initializeMedia()` can replace the plugin during navigation under the same impl (`llviewermedia.cpp:1751`). MIME, filename extensions, URL suffixes and cached “was VLC” are not proof of the current source. On Linux the normal MIME mapping may select GStreamer; only `MediaPluginForceVLC` changes that selection (`:1868`). Do not force the setting or accept GStreamer as VLC.

Before any source exists, `LLMIMETypes::implType(mMimeType)` is only a **provisional waiting classification**, applying the same Linux force-VLC resolution rule. Bootstrap demand is allowed only for a provisionally LibVLC candidate whose face and normal media policy permit it. Unknown/unresolved MIME waits for the ordinary media system; other plugin mappings receive no bootstrap demand and show unsupported status. Once a source exists, actual resolved plugin identity replaces the provisional decision. An unsupported web face must never be started by this feature's demand.

### Reconcile before media interest/update work

At the **start of every `LLViewerMedia::updateMedia()`**, after shutdown handling and before the impl update/interest loop (`llviewermedia.cpp:682`, `:714`), reconcile all bounded media-slot subscriptions. Per slot:

1. Re-resolve the object and face; check object alive, live volume, TE in range, media entry still present and associated media ID valid.
2. Re-resolve via `LLVOVolume::getMediaImpl(te)` and compare its current impl/source epoch with the previous subscription token. Check the actual source is still LibVLC, or the restricted provisional waiting case above.
3. Check policy, enabled/running slot state and active output/preview demand. Only then contribute demand. On any validation failure, **drop the old demand immediately**, invalidate the slot/derived-cookie readiness and release its retained texture. On a changed impl/source, release the former subscription before adopting the new one with a fresh epoch and waiting for its completed frame.
4. If plugin creation/navigation/destruction changes identity during that update, its lifecycle hook revokes stale demand/readiness before further use; the render preparation checks identity/epoch again before copying. No demand survives until some later UI refresh.

**Do not hold a strong `viewer_media_t` in a slot, binding, pending copy or demand table.** Do not retain an `LLFace*` or unvalidated raw impl pointer. Re-resolved impl access is scoped to the main-thread reconcile/copy operation; subscription bookkeeping uses an invalidatable identity token and generation, with teardown removal. Upload jobs retain their existing impl/texture protection plus the pending-upload mapping retention required in section 4; that job ownership never contributes playback demand.

Keep only an `LLPointer<LLViewerMediaTexture>` as the borrowed source resource across frames. This prevents its removal by the media map's **30 s inactive purge** when only the map would otherwise hold it (`llviewertexture.cpp:3777`); it does not own the impl or grant continued playback. Source removal drops this pointer as well as demand. This is an audio correctness requirement: `LLVOVolume::removeMediaImpl()` removes the source object (`llvovolume.cpp:3111`), and proximity calculation defaults to zero when no objects remain (`llviewermedia.cpp:4113`). A strong orphaned impl plus demand could otherwise keep full-volume audio alive.

### Existing consent and ownership remain authoritative

The slot only observes the player's full content image. It never navigates, resizes, re-volumes, starts/stops or sends input to the source. Prim texture repeats, tint, material and screen geometry do not modify the sampled source image. Existing autoplay requires the entry flag and viewer preference (`llviewermedia.cpp:4395`); if a click is required, show **Needs source click** and direct the user to existing media controls.

Preserve mute, disabled/failed media, media-class preferences, parcel obscurity, explicit visibility/suspended updates and global media switches (`llviewermedia.cpp:3101`, `:3115`, `:3608`, `:3634`). Existing controls retain `MEDIA_PERM_CONTROL` / `MEDIA_PERM_INTERACT` checks (`llpanelprimmediacontrols.cpp:329`, `llvovolume.cpp:2936`), and the source keeps its entry whitelist (`llmediaentry.cpp:461`, `llvovolume.cpp:2996`). No fake focus, UI ownership or repeated `setVisible()` calls may override that policy.

## 3. Source aspect and the texture contract

### Real aspect is independent of buffer size

**Current bug to avoid:** LibVLC calls `libvlc_video_set_format(..., "RV32", mWidth, mHeight, ...)` with the requested buffer size (`indra/media_plugins/libvlc/media_plugin_libvlc.cpp:353`, `:568-586`), and never reports natural video size. The wrapper uses an explicit MoaP entry size or defaults to **1024x1024** (`indra/llplugin/llpluginclassmedia.cpp:360-374`), with optional power-of-two scaling (`:402`). Neither the used buffer dimensions nor the allocated texture dimensions prove the video's aspect. Treating a square buffer as a square video distorts ordinary 16:9 footage.

**Required metadata extension:** query `libvlc_video_get_size()` when valid video geometry becomes available and when it changes; send a dedicated source-video-size/aspect metadata message through `LLPluginClassMedia` to the impl's published source state. Send on the plugin's normal message thread, not an unsafe decoder callback. Clear/reset on load/source replacement; carry the producing load token from section 4 and reject stale metadata. This must **not** call player `setSize()`, reuse a wrapper natural-size path that triggers resizing, or alter the borrowed player's MoaP buffer.

Each media slot has **Source aspect: Auto / 16:9 / 4:3 / 2.39**, default **Auto**. Auto uses valid plugin-reported video width/height; while that metadata is unavailable, it falls back to **16:9**, explicitly indicated in status/tooltip. Invalid/zero sizes do not replace the fallback. Manual selections override metadata, remain per slot and persist with scenes. Metadata arrival or an override change increments the slot layout/framing revision and recomposes from the current completed image even if no new decoded frame arrives.

Sample the **whole content region** of the requested VLC buffer and interpret it using this source aspect. Do not crop a 16:9 rectangle out of a 1024x1024 buffer: the plugin rendered the full video into that buffer, so the aspect belongs to the interpretation of all its pixels. Exclude allocation padding only. Buffer/content size remains necessary for UV bounds and texel centers, independent of natural geometry and logical slot aspect.

For source aspect S and destination aspect D, FIT occupies `(1, D/S)` when S>D, otherwise `(S/D, 1)`; FILL takes the corresponding crop using the existing anchor; STRETCH fills the destination. Quarter turns swap S before fitting. Use the existing fit algebra (`llprismlens.cpp:10425`) for displays, previews and projectors. Keep the light scale-X/scale-Y aspect convention (`:11072`) and square cookie allocation. Black projector FIT bars emit no light. Media has no FOV; CAMERA_FOV/throw-follow-camera controls are unavailable.

## 4. Completed images, accepted publications and scheduling

### Publish only completed uploads

`MEDIA_EVENT_CONTENT_UPDATED`, plugin dirty state, render frame count and `LLViewerMediaImpl::isUpdated()` do not prove a completed GL image. Dirty rectangles are consumed before upload (`llviewermedia.cpp:3185-3206`), and `setUpdated(true)` also marks face setup (`llvovolume.cpp:3191`). Add main-thread published media state: completed-image serial, ready flag, plugin/source identity, load token, source/layout epoch, used dimensions/region and video-aspect metadata.

**Pixel provenance (CODEX P1-C):** same-plugin navigation can reuse the shared buffer. `LLPluginClassMedia::loadURI()` sends only the URI and does not clear dirty state (`llpluginclassmedia.cpp:792-799`); `updated` accepts untagged rectangles (`:1106-1145`). VLC's display callback emits those rectangles without load identity (`media_plugin_libvlc.cpp:159-163`, `:201-214`), and `load_uri` reuses the pixel mapping (`:617-620`). Merely assigning a new viewer epoch can therefore relabel old pixels as new.

- Issue a non-reused **per-load token** before sending each LibVLC `load_uri`. Clear pending dirty/retry state and geometry, advance the source epoch and immediately invalidate derived slot/cookie readiness, even if the impl, plugin and buffer are unchanged.
- Carry that token into an immutable VLC player/callback context and every frame-bearing `updated` notification. Quiesce old-player callbacks before reusing their context/shared buffer; an old callback or queued notification must retain its old token, never read a mutable current token. Require a real frame produced by the new load; time/duration-only notifications and existing buffer contents cannot establish readiness.
- Reject missing/stale frame tokens for LibVLC before merging dirty rectangles or reporting content updated. Preserve the accepted token in dirty state, the captured upload descriptor, GL-name promotion and completed-image publication, checking it with plugin identity and source/layout epoch at each handoff. Never stamp an incoming old notification with the receiver's current token. Other plugins retain their existing message contract.

- **CPU main path:** propagate a success result through `doMediaTexUpdate()` (`llviewermedia.h:280`; `llviewermedia.cpp:3215`). Allocation/upload failure must return failure, not merely log and then advertise readiness (`:3235`). Advance the serial only after a successful update and `syncTexName()` (`:3160`, `:3250`).
- **CPU worker path:** carry that success flag, producing load token and captured source/layout epoch from the worker through the main-thread completion (`llviewermedia.cpp:3133-3157`). Publish only after the GL-name swap/fence ordering has completed. `LLImageGL::syncToMainThread()` posts the swap after synchronization (`llimagegl.cpp:2016`, `:2057`); verify queue ordering explicitly and, if needed, attach publication to swap completion rather than the upload job's submission/return. Check identity/token/epoch before GL-name promotion too; a failed, resized, navigated or destroyed old job cannot publish into the current source.
- Reset readiness on source/layout/GL-resource replacement until a matching successful upload exists. A dirty notification, placeholder allocation or cleared dirty bit never increments completed serial.

**Failed-upload recovery (CODEX P1-D):** `preMediaTexUpdate()` clears dirty state at `llviewermedia.cpp:3206`, before `postTo()`/upload; the enqueue result at `:3139` is ignored and allocation failure at `:3235` only logs. A paused/final frame may never notify again. Transfer dirty work into one pending descriptor rather than forgetting it. On enqueue or upload failure, retain/re-dirty its rectangle under the same identity/load token/layout epoch, merging newer matching dirties without clearing them on completion. Retry from the normal policy-gated media update, at most once per impl per eligible update at the existing cadence, with one coalesced retry record and no spin or additional pending job. Reacquire the current matching mapping for each attempt; retain no extra pixel buffer for retry. Discard obsolete retries on load/layout/source replacement or teardown. Readiness/serial advance only on success; transient failure recovers without another decoder notification, including while playback is paused.

**Pixel lifetime (CODEX P1-3, simplified by OPUS P1-B): retain mappings for the one pending upload**, independent of player/process lifetime. `preMediaTexUpdate()` obtains a raw address (`llviewermedia.cpp:3195`); the queued job retains only impl/texture (`:3137-3146`). The worker lock (`:3218`) starts too late to protect a queued address. Resize requests removal (`llpluginclassmedia.cpp:257`), the remove response destroys the mapping (`llpluginprocessparent.cpp:1228-1241`), and parent destruction also destroys mappings (`:118-132`). Completion-time epoch rejection cannot prevent that use-after-free.

- Register the pending upload's mapping with the plugin parent **before exposing its address, consuming dirty state or enqueueing**, through `getBitsData()`'s replacement (`llpluginclassmedia.cpp:332-339`). Synchronize registration with retirement and capture address, byte extent, mapping generation, dimensions/formats, load token and epoch in the immutable upload descriptor. Bounds-check every referenced row/rectangle against that extent using checked arithmetic before dereferencing; the worker reads only the captured descriptor, never current plugin fields.
- The parent retains a retired mapping referenced by that impl's pending upload at `shm_remove_response` (`llpluginprocessparent.cpp:1235`), destroying it only after the pending-upload completion callback releases it. Use the same retirement in the parent destructor (`:127`): transfer only the still-needed mapping to the completion cleanup record, without retaining the parent/player/process. Unreferenced regions follow ordinary removal; repeated resize/navigation retains **at most one retired mapping per impl**. No new upload starts while the old one is pending, including across source replacement (`mTextureUpdatePending`, `llviewermedia.cpp:3136`, `:3171`).
- Completion releases retention on success, failure or obsolete result. Dropped enqueue releases immediately; cancellation/queue shutdown must run equivalent terminal cleanup only after pixel reads have stopped. Main-thread uploads retain through their synchronous return. Never wait for a worker on the main thread. This one-pending-upload bound needs **no aggregate byte ceiling or upload-admission branch**; ordinary prim/CEF CPU uploads must not be starved by media-slot bookkeeping. Token/epoch checks still reject obsolete GL-name promotion/publication.

The current VLC callback exposes shared CPU pixels while the decoder can write another frame (`media_plugin_libvlc.cpp:141-163`). **Existing VLC frame tearing is a known limit.** Mapping retention prevents unmapping, not concurrent same-load decoder writes. Fixing same-load decoder frame coherence is outside this feature; load provenance and old-callback quiescence remain required. Acceptance distinguishes inherited source tearing from a new lifetime/copy/publication defect.

### Prepare before every consumer, including media-only configurations

At `LLPrismLens::renderAuxiliaryView()` (`llprismlens.cpp:9727`), perform media slot demand/preview preparation, eligible frame copies and dirty media projector-cookie preparation **before the no-captures return at `:9760`**. Preserve master-enable/deferred-context checks and the **`sPrismLensRender` / `gCubeSnapshot` exclusions** before doing any work. Split “has source slots” from “has camera captures”: zero cameras does not disable media, preview-only operation or light-only media scenes.

## 9. Recording limits and open questions

External hardware capture records display/audio in real time; it does not synchronize VLC decode, network buffering, media upload, VCam publication, viewer presentation and recorder clocks. Expect repeated/dropped frames and variable start/latency. Image rate is bounded by completed source frames, slot entitlement and viewer renders. Audio can continue while images stall. A saved scene, fixed viewer FPS or paused simulation is not frame-exact media replay.

For a repeatable take, use a stable seekable source, preload and verify it through the original controls, cue a visible flash + audible clap/timecode, keep the viewer active and measure offset/drift at both ends of a long recording. Capture the actual audio device used by the viewer without duplicate monitoring. Diagnostics expose source epoch/load token, rejected stale frames, resolved plugin, reported/fallback aspect, completed/slot-accepted/cookie-accepted serials, upload failures/retries, preflight/allocation failures, effective cadence and image age. Frame-locked/offline decoding and HDR/wide-gamut conversion are outside this first implementation.

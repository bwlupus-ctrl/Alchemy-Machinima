# Director Kit P0: v1 UI-time regression diagnosis

Scope: `9c25f75491a..32b7fb162ae`, `DirectorUIV2=false`, read-only source/call-path audit. The supplied login-screen measurements are real deltas, but the candidate diff contains **no new v1 steady-draw O(views) work capable of explaining them**. In particular, the standalone Cinematic Camera `operator_tab` has no changed C++/XUI implementation in this range and contains no `ALCompassDial`; that datapoint cannot be caused by the proposed compass change. The result therefore does not support naming any listed candidate as the exact common cause without a same-binary rerun/profile or a commit bisect.

## Interpretation and verification target

The only new code unconditionally reached by every v1 Director draw is two boolean branches; the only new code reached by Cinematic Camera Operator from the named candidates is the global clean-water pending check, which also reaches every unaffected window. Thus the observed pattern has no causal match in this diff. Before changing product code, compare `views_drawn_mean`, `views_culled_mean`, `find_calls_mean`, and `find_visited_mean` between the two CSVs, then capture per-zone UI totals or bisect `9c25f75491a..32b7fb162ae` using the same executable/settings. A nonzero steady `find_calls_mean` would falsify the call-path result and identify an unlisted caller; unchanged view/find counts plus a repeatable delta points to rendering/compiler/build variance rather than the proposed walks.

# TPVP / Terms of Service Technical Risk Screen: Absolute Cinema SL (2026-10-18)

**Status:** Read-only technical screen. No source, settings or build file was changed. This file is the only new file.
**Not legal advice.** Risk ratings describe how a feature's code behaves and how close it sits to a stated policy rule. They are not conclusions about breach.

## 0. Method and definitions

- **LOCAL** means the code path changes only the viewer's own rendering, motion or files. No `gMessageSystem` send, `AgentAnimation`, `ViewerEffect`, `ObjectUpdate`/`MultipleObjectUpdate`, `ChatFromViewer`, `AgentPreferences` POST or other capability request was found on that path.
- **GRID** means the path sends something the simulator or a capability receives. Where a grid-visible send exists, the file:line is given.
- "No send found" comes from grep plus targeted reads. It is not a runtime or packet-capture test. Whether other residents see an effect is inferred from the message type and standard Second Life protocol semantics, not observed in-world.
- Clause quotes are short phrases (under 15 words). Where the source is a summarising fetch, this is noted in section 1.

## 2. Highest risks at a glance

1. **Distributor disclosures and naming (High if distributed).** No "not provided or supported by Linden Lab" text exists in the viewer, skins, settings, docs or README. README.md:19 says "not a TPV-compliant viewer". The product name "Absolute Cinema SL" (README.md:2, 5) contains "SL", which TPVP 5(b) names. No privacy policy file exists in the repo.
2. **Linden logos outside the connect path (Medium).** `skins/default/xui/en/panel_login.xml:112` uses `login_sl_logo_horizontal` on the login screen (connect path, allowed). `llchathistory.cpp:853` and `llchatitemscontainerctrl.cpp:450` set the `SL_Logo` icon on system chat lines (not connect path). TPVP 5(f) restricts Linden splash use to connecting.
3. **Recording other residents without consent (Medium).** Dance Ball, clones, cast actors and actor masks all exist to film other residents. No consent or notice gate exists in `al*`, `llghost*`, `lldirector*` or `alvcam*` (grep for "consent" returns nothing). The Snapshot and Machinima Policy makes consent from recognisable residents the user's obligation.
4. **VCam plays borrowed prim-face media (Medium).** `llprismlens.cpp:3006-3008` reads another object's `getTE()->getMediaData()` and `llprismlens.cpp:3101-3106` reuses that object's `getMediaImpl()`. Playback is local, but the media is external streamed content that the machinima licence does not cover.
5. **VCam HTTP(S) downloads are on by default (Medium).** `alvcammediafileio.h:15` sets `allowDownloads = true`. `alvcammediafileio.cpp:791-902` downloads via libcurl and `:393` writes a cache file. Third-party copyright exposure; the viewer does not check licence.
6. **Destroy / explosions gate only the first object (Medium).** `alviewermenu.cpp:272` checks `permYouOwner()` only on `getFirstRootObject()`. The operation then acts on the whole selection (`selectionUpdateTemporary`, `sendDelink`, and `sendMultipleUpdate(UPD_POSITION)` at `:313`). Objects the user can modify but does not own may be affected. Server permissions still apply.
7. **RLVa is on by default and sends automatic grid messages (Medium).** `settings.xml` `RestrainedLove` Value 1 (around lines 6435-6446). `rlvcommon.cpp:734` sends `ChatFromViewer` on script channels (`sendChatReply`). `rlvcommon.cpp:722-730` sends automatic busy IMs (`sendBusyMessage`). `rlvhandler.cpp:2830` sends hover height and `rlvhandler.cpp:3311` sends `AgentRequestSit`.
8. **External automation API (LEAP), off by default (Medium if enabled).** `settings.xml:14522` `LeapCommand` defaults to an empty array with Persist 0. `llappviewer.cpp:1312-1317` starts it only from that setting. When started, `llagentlistener.cpp` exposes `getNearbyAvatarsList` (:189), `playAnimation` (:171, which sends `AgentAnimation` at :733), `requestTeleport` (:64) and `lookAt` (:130).
9. **`/regionmsg` estate broadcast (Medium).** `alchatcommand.cpp:254-270` sends `EstateOwnerMessage` "simulatormessage" to the region. The handler has no viewer-side estate-manager check. Server acceptance is assumed, not tested.
10. **Crash reporting and channel identity (Medium, conditional).** BugSplat is compiled in only when `BUGSPLAT_DB` is set (`indra/CMakeLists.txt:89-97`). Presets and `cxs/*.ps1` do not set it. If set, `llappviewerwin32.cpp:798-814` engages BugSplat, and attachments include the log and settings (`llappviewersdl.cpp:371-382`). `CrashSubmitBehavior` defaults to 1, "always send" (`settings_crash_behavior.xml`). The build channel is `VIEWER_CHANNEL "Alchemy Test"` (`indra/CMakeLists.txt:15`), and TPVP 1(b) requires a unique identifier. Uniqueness is unverified.

Good news from the code: no grid-visible send was found in Dance Ball, clone/Ghost Studio, Actor Mover gaze, prop mover, flycam, actor mask/silhouette or Director animation switching. No automatic chat exists apart from RLV replies. ViewerStats is kept. The updater is disabled.

## 5. Clauses cited (quick reference)

- **TPVP 1(b)**: each version needs a "unique viewer identifier" not shared with another viewer.
- **TPVP 1(c)(1)**: distributor disclaimer "not provided or supported by Linden Lab" on the download page or before install.

## 6. Could not verify

1. **Verbatim policy text.** TPVP, Community Standards and the Second Life Policy page were read through a summarising fetch. Quotes are as returned. Check the live pages before relying on any quote.
2. **Full Terms of Service.** The ToS text was not retrieved. The Section numbers above are as the Second Life Policy page cites them.
3. **Wiki-copy policies.** The Scripted Agent Policy (last edited 2023) and the Snapshot and Machinima Policy (last edited 2011) are wiki copies and may be superseded.
4. **RLV, VCam, media streams and Dance Ball.** None of the fetched texts names them. Whether they are restricted is unknown.
5. **Distribution and build flags.** Whether the owner distributes builds, and whether any distributed build sets `BUGSPLAT_DB`, `CrashSubmitBehavior` or `USE_VELOPACK`, was not confirmed. Only source, presets and `cxs/*.ps1` were checked.

7. **On-grid visibility.** Inferred from message types and protocol semantics. No in-world test or packet capture was run.
8. **Login payload and channel uniqueness.** The login payload was not traced end to end. Whether "Alchemy Test" collides with upstream Alchemy was not checked.
9. **Partially traced items.** Silhouette, mask and light response (grep only). Temporal capture and world time (no grid send found, not traced in full). Movement style, pose polish and gravitate lean (not traced). Actor Mover self-walk (partly traced).

## 7. Notes

- The main concern is distribution, not the feature set. The largest creative features (Dance Ball, clones, gaze, prop mover, flycam, masks) are local in the code paths reviewed. Their exposure is mostly recording consent and how footage is presented, not grid traffic.
- The "SL" name, the missing disclaimer and the logos are cheap to fix before any distribution.
- Nothing in the reviewed code automatically sends chat or IMs except RLV replies, so the Scripted Agent message cap is not reached by default.
- No telemetry or analytics host was found in the source (grep for telemetry, analytics, sentry, bugsplat, posthog and similar). The only off-grid upload path is BugSplat, which is off unless configured.

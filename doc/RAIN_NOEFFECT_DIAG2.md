## Per-frame chain and every rain gate

1. In a normal non-snapshot display, `display()` generates sun shadows and then the rain-cover map at `indra/newview/llviewerdisplay.cpp:858-866`. It later renders deferred geometry, flushes the G-buffer, and performs deferred lighting at `llviewerdisplay.cpp:1102-1143`; `render_ui()` calls `gPipeline.renderFinalize()` before HUD/UI composition at `llviewerdisplay.cpp:1787-1829`.
2. `renderFinalize()` disables depth/blend/cull, computes HDR state, optionally copies SSR, then calls `renderWeather(&mRT->screen)` at `indra/newview/pipeline.cpp:22650-22669`. Thus the destination is the live linear scene-color target, not a disposable Director target. Rain is then included in luminance/exposure/bloom (`pipeline.cpp:22795-22850`), tonemapped from `mRT->screen` into `postPingMap` (`pipeline.cpp:22932-22935`), processed through AA/CAS/DoF ping-pong (`pipeline.cpp:22968-23030`), and presented from the final `sourceBuffer` (`pipeline.cpp:23140-23149`).
3. `renderWeather()` first returns for master off (`pipeline.cpp:18978-18994`) or cube capture/null target/missing fullscreen triangle (`pipeline.cpp:18995-18998`). Given the facts and an ordinary world view, none applies. There is no v1/v2 Director branch and no water-level/underwater gate.
4. Rain intensity is `rainEnabled ? clamp(RainIntensity,0,1) * cloudFactor : 0` (`pipeline.cpp:19242-19244`). `cloudFactor = lerp(1, clamp(currentSky.cloudShadow,0,1), clamp(EEPCoupling,0,1))` (`pipeline.cpp:19085-19100`); absent sky leaves it 1. With intensity 0.83 and coupling 0.8, the exact range is **0.166..0.83**, so EEP cannot zero it. There is no rain start timer/ramp. Presentation time drives only procedural phase (`pipeline.cpp:19102-19106`, `19528-19530`); the lightning controller does not gate rain. The inverted lightning min/max is clamped to a valid max at least equal to min (`pipeline.cpp:19125-19129`) and is irrelevant to rain.
5. Occlusion usability requires setting on, valid map, same `gFrameCount`, allocated texture, finite positive depth range, complete occlusion shader, and a mapped `WEATHER_RAIN_OCCLUSION_MAP` channel (`pipeline.cpp:19266-19280`). Failure here does **not** directly kill rain: it selects the baseline program and coarse shelter fallback (`pipeline.cpp:19292-19300`, `19360-19369`). However, if the map/consumer is unavailable and default `ShelterFade` is on, an upward 48 m camera ray can make `exposed=0`; its 0.2 s exponential smoother is at `pipeline.cpp:207-247`, ray/gate at `19301-19359`. 6. The final CPU rain gate is `rainPassIntensity > 0 && rainProgram.isComplete()` and the whole function returns only if rain, surface, and lightning are all inactive (`pipeline.cpp:19360-19382`). The successful cached-binary load/no link errors strongly clears program completeness, though an in-world program-completeness probe would be definitive.
7. With divisor 1, the supplied setup bypasses allocation and upsampling: `rain_target` is directly `mRT->screen` (`pipeline.cpp:19440-19465`). The pass disables depth test and scissor, enables blending, selects additive `BT_ADD`, writes RGB but not alpha, binds deferred inputs, uploads current inverse projection/modelview plus intensity/density/distance, and draws one fullscreen triangle (`pipeline.cpp:19473-19559`). Wind scale 0 merely makes vertical rain (`pipeline.cpp:19513-19516`); density 0.7 and distance 144 remain positive.
8. In the fragment shader, reconstructed scene distance must be positive and intensity positive, and the ray must extend beyond 0.75 m (`indra/newview/app_settings/shaders/class1/deferred/weatherRainF.glsl:240-258`). It marches 4..24 samples from camera to the nearer of scene depth and max distance (`weatherRainF.glsl:260-301`), applies per-sample cover exposure when compiled, and emits bounded positive RGB with alpha 0 (`weatherRainF.glsl:303-314`). Bad/missing reconstructed depth could make every fragment return zero, but no 10/07-10/10 change moved the pass before deferred depth production.
9. For divisors 2..4 only, rain first renders into cleared `mWeatherRainHalf` (`pipeline.cpp:19442-19471`), then the upsample shader binds it through `WEATHER_RAIN_MAP`, resolves with scene-depth-aware weights (`weatherRainUpsampleF.glsl:20-58`), and additively draws to the same caller target (`pipeline.cpp:19563-19592`). This path is not active for the user's divisor 1.

## Suspect A: rain-occlusion map

**Static verdict: implementation is self-consistent, but this remains the leading runtime discriminator because it is the only supplied non-default switch capable of multiplying every rain sample by zero. Confidence: medium, not proven without the A/B/readback.**

- Producer gates: both master and occlusion must be on (`pipeline.cpp:27742-27752`); Rain must be on with finite positive configured intensity, deferred rendering must be active, this must not be a cube snapshot, at least one rain/surface occlusion consumer must have a mapped sampler, and all shadow programs must be complete (`pipeline.cpp:27767-27805`). Failure releases/invalidates the map and makes the rain pass fall back rather than sample bad depth. A failed 1024 allocation is remembered and skipped (`pipeline.cpp:27810-27831`), again causing fallback, not map-driven zero.
- Target: it is a dedicated D24 depth-texture render target, no color attachment, explicitly configured for point filtering, clamp addressing, and `GL_TEXTURE_COMPARE_MODE=GL_NONE` because the shaders do manual `sampler2D` comparison (`pipeline.cpp:27821-27840`; `indra/llrender/llrendertarget.cpp:186-242,294-302,394-418`).
- Camera/volume: extent is clamped to 32..320 m; at the supplied extent 320, rain distance 144, and shelter height 48, vertical half-range is 352 m (`pipeline.cpp:27843-27894`). The camera-centered origin is snapped in global space, converted back to agent space, then moved 352 m upward (`pipeline.cpp:27853-27896`). `look(...,-Z,+Y)` plus `glm::ortho(-extent,+extent,...,near=.1,far=704.1)` produces the published `projection*view` used by both rasterizer and sampler (`pipeline.cpp:27898-27904`). There is no `GLM_FORCE_DEPTH_ZERO_TO_ONE` build define (`indra/cmake/00-Common.cmake:102`), no reverse-Z setup, and this pass explicitly uses `GL_LESS` (`pipeline.cpp:27952-27959`).
- Clear/render: the bound D24 target is cleared with `GL_DEPTH_BUFFER_BIT` under enabled depth writes, hence OpenGL's conventional all-far value 1 (`pipeline.cpp:27952-27966`). A top-down orthographic cull camera uses the same origin/direction/near/far and derives planes from the same current matrices (`pipeline.cpp:27968-27986`; `indra/newview/llviewercamera.cpp:206-233`). The pass excludes rigged and alpha-blended/cutout geometry and renders two-sided static opaque world casters. It publishes the map only if at least one caster batch exists; an empty all-1 map is marked invalid and fails over (`pipeline.cpp:27978-28020,28084-28087`).
- Comparison sign: conventional ortho depth increases downward. Therefore a higher roof has `map_depth < point_depth`; the shader computes `(point_depth-map_depth)*depthRange` and returns exposure approaching 0 only for a point below that roof (`weatherRainF.glsl:58-107`). Clear depth 1 gives a negative height and exposure 1. NaN/Inf, nonpositive range, invalid matrix, out-of-volume coordinates (including either NDC side), and invalid texture size/depth all fail open to 1 (`weatherRainF.glsl:46-91`). The sign and bounds are correct.
- Binding: all explicit Weather samplers are exactly `weather_rain_map` and `weather_rain_occlusion_map`; both enum slots exist at `indra/llrender/llshadermgr.h:746-747` and both names are registered at `indra/llrender/llshadermgr.cpp:1997-1998`. Rain binds D24 as depth with point filtering and enables comparison only when the returned channel is nonnegative (`pipeline.cpp:19480-19504`); surface does the same (`pipeline.cpp:19605-19632`). Upsample binds its RGBA rain texture through `WEATHER_RAIN_MAP` (`pipeline.cpp:19572-19589`). The log phrase “Add it to ... (see WEATHER_RAIN_MAP)” is generic diagnostic text for *any* unreserved active sampler (`indra/llrender/llglslshader.cpp:821-826`); without the sampler name it does not indict either Weather sampler. Cached-binary load still remaps active uniforms/channels (`llglslshader.cpp:881-930`).
- Shader lifecycle: baseline rain always loads; the occlusion permutations load only when the setting is on (`indra/newview/llviewershadermgr.cpp:4453-4494`), and toggling the setting requests a shader rebuild (`indra/newview/llviewercontrol.cpp:1217-1220`). The logged successful Rain Occlusion load therefore agrees with the saved setting.
- Shadow changes: `git blame` assigns the camera/projection/clear/compare producer to `756fedf7a906`; `11cb6fa2c90`, `081da233896`, and `a240fb3964d` changed sun-shadow distance/bias/upload behavior, not this matrix. `de2e5b16ea7` changes the sun cascade's perspective-vs-ortho choice and early `glFlush`, not `generateWeatherRainOcclusion()`. `53300f503521` replaced the rain attachment boolean with `sShadowDrawFilter=1` at `pipeline.cpp:27979-27987`; its predicate still skips exactly attached draws (`indra/newview/lldrawpool.cpp:498-510`) and does not reverse or clear the depth map.

## Suspect B: EEP coupling

**Cleared.** The only environment input to rain intensity is `LLSettingsSky::getCloudShadow()` from the current sky; there is no region-weather scalar, parcel scalar, precipitation field, or sky-transition timer in this chain (`pipeline.cpp:19085-19100,19242-19244`). Both operands are clamped and `cloudFactor = (1-coupling) + coupling*cloudShadow`. Consequently clear-sky/cloud coverage at its most suppressive value 0 with coupling 0.8 leaves factor 0.2 and rain intensity `0.83*0.2 = 0.166`, well above both CPU and shader zero gates. Setting `AlchemyWeatherEEPCoupling=0` is still a useful second A/B because it raises intensity to 0.83 and makes faint-output explanations obvious, but it cannot explain mathematically zero rain with the supplied value. No EEP fade/ramp is applied to rain; only the independent shelter smoother can converge exposure toward zero (`pipeline.cpp:207-247,19342-19369`).

## Minimal correct fix and cheap in-world A/B

There is not enough evidence to justify changing the projection, depth sign, matrix, or sampler binding: each is internally correct in source. The minimal **safe source mitigation, conditional on the A/B proving the occlusion path**, is to make that path fail open at `indra/newview/pipeline.cpp:19269-19280`: reject the occlusion permutation/map when the generated depth is pathologically all-covering, so the existing baseline shader and coarse exposure path at `pipeline.cpp:19292-19369` run instead. The validity assignment at `pipeline.cpp:28084-28087` currently proves only that at least one caster batch was submitted, not that usable depth landed in the texture; a production fix should add the depth-sanity result there and leave `mWeatherRainOcclusionValid=false` on failure. The existing diagnostic readback/min-max scaffold at `pipeline.cpp:28022-28053` is the exact place to establish the GPU-side failure before choosing whether the eventual underlying correction is producer state or cached shader binary. As an immediate zero-risk operational mitigation, leave `AlchemyWeatherRainOcclusion=0`; changing its default at `settings.xml:29159-29164` alone would not repair an already saved value.

For a decisive in-world test, move the camera into unobstructed sky above all roofs, leave master/rain on, and temporarily set `AlchemyWeatherShelterFade=0` so the coarse ray cannot confound the result. Toggle only `AlchemyWeatherRainOcclusion` from 1 to 0. Immediate rain on OFF proves the failure is the occlusion program/map path; no change clears it and redirects diagnosis to scene-depth reconstruction or a stale cached rain binary. Then set `AlchemyWeatherEEPCoupling=0`: this should increase intensity from at least 0.166 to 0.83 but cannot turn a mathematically zero pass on. Optionally switch `AlchemyWeatherRainResolutionDivisor` from 1 to 2: rain only at 2 would implicate the direct-target path; no rain at either keeps the fragment output/depth reconstruction in scope.

# Animation loop-point stutter: source diagnosis

2026-10-17; checkout `5fdb2da36d11b96206172bbe3b801c03edeb69fd`. Read `CLAUDE.md` first. Source inspection only: no viewer run, instrumentation, build, code changes, commit, or push.

Tester bug (verbatim): 'something that I noticed since many versions ago, but I never worried too much, was the animation repeats stuttering a bit before starting the new cycle'

**Assessment:** a brief pose hold or velocity discontinuity is better supported than a loop-triggered CPU stall or clock reset. The strongest fork-specific suspect is Loop seam; the strongest stock-like suspect is the asset's seam plus noncyclic curve sampling. These are hypotheses about the reported symptom, not confirmed runtime causes. Loop seam entered in commit `9920eb65583` (2026-08-22); reproduction in a verified earlier build would demote it immediately.

**Critical settings facts:** shipped `ALPolishEnabled`, `ALPolishInertiaEnabled`, and `ALPolishLoopSeamEnabled` are **true**, despite cached-control fallbacks/comments saying false (`indra/newview/app_settings/settings.xml:8720`, `:8753`, `:8841`). Contact, Phase match, and Secondary are also shipped on. Actual saved user settings may differ. Loop seam's runtime gate is **master AND Loop seam**, independent of Inertia (`indra/newview/llvoavatar.cpp:5692`–`:5696`); the tooltip claiming Inertia is required is stale (`indra/newview/app_settings/settings.xml:8835`). Turning off Inertia alone does not isolate seam repair.

**Likely causes, ranked**

1. **Loop seam deliberately repeats the preceding pose — high when enabled; pose hitch.** At a detected wrap it captures the previous *motion joint-state* pose, sets elapsed to zero, samples the new curve, then blends back to that fixed snapshot (`indra/llcharacter/llkeyframemotion.cpp:826`–`:852`). `applySeamEase()` starts at weight 1 and advances elapsed **after** writing the pose (`:1369`–`:1415`): each flagged channel therefore repeats its previous sample on the first post-wrap update, followed by a 0.15 s smoothstep recovery (`:78`). This guarantees continuity at that stage but creates a velocity stop/catch-up; it is not interpolation through the loop boundary. Only joints exceeding seam pose/speed thresholds participate (`:1149`–`:1168`). This precedes the current update's constraints/final blend/Polish/gaze; prior joint states can already contain constraint results (`:1831`), so the snapshot is not necessarily the final displayed avatar pose.

   **Confirm:** hold all other settings fixed, toggle only Loop seam, watch ten cycles; then disable Inertia separately. **Minimal remedy:** leave Loop seam off if it causes the hitch. A code fix should evaluate a correction at the actual wrap overshoot and preserve incoming velocity, instead of forcing the last frame's fixed pose for a whole update. Advancing elapsed before blending removes the forced duplicate but alone does not establish velocity continuity.

2. **Authored endpoint/tangent mismatch or a held tail in stock sampling — high if it survives Polish off; pose hitch.** Stock wrapping preserves overshoot: for positive loop length, `loop_in + fmod(time - loop_out, loop_out - loop_in)` (`indra/llcharacter/llkeyframemotion.cpp:796`–`:806`). Example: in=0.2, out=2.2, time=2.217 gives 0.217, not 0.2. Equality at the first out point samples that endpoint; zero-length loops hold the out point. There is no demonstrated full-frame-loss bug in this modulo itself.

   Rotation/position/scale curves clamp before the first and after the last key; otherwise they interpolate adjacent stored keys (`indra/llcharacter/llkeyframemotion.cpp:175`–`:212`, `:255`–`:292`, `:336`–`:373`). Their apparent loop-in interpolation branches at `:205`, `:285`, `:366` are unreachable: `right == end()` was already handled by the outer branch. Cached loop keys (`:3039`–`:3045`, `:3076`–`:3082`) therefore do not provide circular interpolation. A last key earlier than loop-out produces a pre-wrap hold; mismatched poses produce a snap, and matched poses with incompatible velocities produce a perceptual hesitation. This is asset-dependent, not proof every loop is broken. Current BVH import already aligns duration with the final playable frame (`indra/llcharacter/llbvhloader.cpp:49`–`:53`, `:876`, `:1370`); do not blindly subtract another frame.

   **Confirm:** same asset in a stock SL viewer; compare with a verified seamless simple clip. Inspect endpoint poses, endpoint velocities, and last-key times versus loop-out. **Minimal fix:** correct that asset's loop window/endpoint keys/tangents first. If viewer repair is needed, add explicitly loop-aware sampling with virtual boundary keys, preserving nonloop clamps and intros/outros. Do not simply enable the dead blocks or change `>` to `>=`. Also log malformed bounds: deserialization checks finiteness but not ordering here (`indra/llcharacter/llkeyframemotion.cpp:2012`–`:2035`); guard invalid bounds while preserving intentional zero-span holds.

3. **Inertia classifies the seam as a transition and repeats the previous displayed pose — medium/high; pose hitch even with Loop seam off.** The post-blend inertializer runs with automatic jump detection (`indra/newview/llvoavatar.cpp:5252`–`:5258`). Its threshold is 0.12 rad plus velocity slack (`indra/newview/alposecontinuity.h:54`–`:56`, `:206`–`:216`); on capture it reproduces the prior displayed pose without decaying that frame (`:219`–`:224`, `:264`–`:268`). Thus an authored seam can trigger a recurring hold, or interact with seam repair's changing velocity. It uses wall-frame dt (`indra/newview/llvoavatar.cpp:5837`), whereas skeletal time can be scaled.

   **Confirm:** master on, Contact/Secondary/Phase match/Loop seam off; compare Inertia off/on. **Minimal fix:** correct the seam input, or disable Inertia for this shot. If instrumented capture is the culprit, evaluate the captured velocity/offset through the elapsed interval on that frame; avoid stacking two independent seam repairs. For scaled playback, give the filter the same animation time domain and explicit pause/reset semantics.

4. **30 fps sampling/frame pacing amplifies a seam — medium as amplifier, low as a wrap-specific origin; time/presentation hitch.** Controller time advances from its own timer delta, uncapped, multiplied by local/global factors (`indra/llcharacter/llmotioncontroller.cpp:874`–`:887`, `:919`). A long frame skips more of the seam; 30 fps makes a one-update hold about 33 ms. The limiter waits at frame end (`indra/newview/llappviewer.cpp:1810`–`:1816`), with monotonic deadlines and no catch-up burst (`indra/newview/alframelimiter.h:74`–`:93`); Windows uses a high-resolution waitable timer with fallback and final spin (`indra/newview/alframelimiter.cpp:77`–`:105`). It has no animation-loop input. VSync/present stalls or wake lateness remain possible, but need measurement. Smoothed/clamped frame globals are distinct from the controller delta (`indra/newview/llappviewer.cpp:5355`–`:5367`).

   **Confirm:** identical shot at stable 30, stable 60, then uncapped; watch frame duration and a second moving subject. **Minimal fix:** address measured sleep/present/work overruns and choose a cap compatible with display refresh. Keep overshoot in animation time; do not reset or clamp the clock at every wrap. Stable frame times with one repeated pose implicate #1–3 instead.

5. **Actual stop/restart or competing playback — medium only with a driver; time/weight hitch.** A native loop does **not** ease out or reactivate every cycle: activation schedules automatic stops only for nonlooping finite motions (`indra/llcharacter/llmotioncontroller.cpp:998`–`:1016`); easing out requires `isStopped()` (`:711`), easing in uses the activation timestamp (`:739`–`:787`). A real stop changes loop handling to advance toward the outro (`indra/llcharacter/llkeyframemotion.cpp:792`–`:794`, `:1460`–`:1478`). A stop followed by start can create a new instance while the old one blends out (`indra/llcharacter/llmotioncontroller.cpp:419`–`:450`).

   Switchboard explicitly stops/starts on slot application (`indra/newview/aldirectoranimswitcher.cpp:410`–`:418`), using an independent auto interval rather than the clip's wrap (`indra/newview/aldirectorswitchermodel.cpp:371`–`:405`). Ghost slot speed changes the whole clone controller (`indra/newview/aldirectoranimswitcher.cpp:396`–`:401`); self slot speed is intentionally unused (`:427`). Ghost retrigger starts only when inactive; a genuine baked loop stays active (`indra/newview/llghostavatar.cpp:3524`–`:3552`). AO cycles on its configured timer (`indra/newview/aoengine.cpp:489`–`:495`), sends start/stop for changed assets, and already skips identical assets (`:962`–`:986`). Simulator animation sequence changes can also request starts (`indra/newview/llvoavatar.cpp:7163`–`:7172`). None is a mandatory native-loop event.

   **Confirm:** play the same loop once directly from inventory, AO/scripted animation devices off, Switchboard disarmed, Dance Ball stopped; compare activation generation, animation sequence, stop flag, and weights at the hitch. **Minimal fix:** remove the proven repeat stop/start, keep a true loop active, and crossfade only actual clip changes. Repeating a nonlooping action through retrigger is inherently a transition; author a loop or provide an explicit crossfade if continuous repetition is wanted.

6. **Actor Mover / Dance Ball external sampling bypasses seam detection — medium for those actors only; pose seam left unrepaired.** Actor Mover samples distance/nominal speed, then wraps into the clip window (`indra/newview/llactormover.cpp:341`–`:360`; seed also wraps at `indra/llcharacter/llkeyframemotion.cpp:1055`–`:1080`). The built-in walk/run speed integrator is correctly bypassed under external sampling (`indra/llcharacter/llkeyframewalkmotion.cpp:197`–`:206`); ordinary walking instead integrates `deltaTime * Walk Speed` (`:209`–`:237`). Dance Ball likewise maps time with F64 modulo (`indra/newview/aldanceballmodel.cpp:396`–`:417`), submits that sample each update (`indra/newview/aldanceball.cpp:1839`–`:1850`), and starts only inactive motions (`:1300`–`:1332`); it does not restart a live loop at every wrap.

   **Proven incompatibility:** keyframe `onUpdate()` substitutes external sample time (`indra/llcharacter/llkeyframemotion.cpp:771`; `indra/llcharacter/llmotion.h:152`–`:154`). At an external wrap that time decreases, but `detectSeamWrap()` rejects negative raw dt *before* testing decreased loop time (`indra/llcharacter/llkeyframemotion.cpp:1266`–`:1277`). Loop seam therefore misses these normal wraps. This exposes #2; it does not make an already seamless asset discontinuous. Actor traversal/gaze cap presentation dt to 0.25 s while native skeletal integration is uncapped (`indra/newview/llactormover.cpp:4688`–`:4702`), a coupling difference on real stalls/high scales.

   **Confirm:** same asset direct versus Mover/Dance Ball, fixed rate/phase, no playlist transitions; inspect native versus effective time. **Minimal fix:** pass an unwrapped monotonic sample clock/cycle index separately from wrapped curve time, distinguish seeks, and use it for seam detection/decay. Only if a measured stall causes traversal/gait disagreement, substep the coupled consumers consistently.

7. **Foot contact / phase matching / Secondary — medium for leg-only sticking; otherwise low.** Contact can classify a grounded dance as planted, explicitly acknowledged in `indra/newview/llvoavatar.cpp:5312`–`:5319`; it ramps IK correction and releases invalid/stale contacts (`:5284`–`:5287`, `:5299`–`:5325`). Mover publishes plant/swing from modulo foot phase and the dominant crossfade lane (`indra/newview/llactormover.cpp:4758`–`:4808`). An ankle seam or plant-window edge can therefore cause a repeat lock/release without changing animation time. Phase match seeds walk/run time **on activation**, not each wrap (`indra/llcharacter/llkeyframewalkmotion.cpp:135`–`:153`), and caches analysis (`:310`–`:324`). Secondary has an independent continuous oscillator with a common-period wrap; it resets on invalid/>0.25 s dt, not on clip wrap (`indra/newview/llvoavatar.cpp:5542`–`:5564`).

   **Confirm:** Contact alone off, then Phase match alone off during uninterrupted walking; test Secondary alone if torso-only. **Minimal fix:** restrict contact to proven locomotion or correct/blend the measured plant transition. Change phase handoff only if activation actually occurs. Keep Secondary phases continuous when handling stalls; there is no evidence for changing its ordinary common-period wrap.

8. **Stepped Animation — high if intentionally enabled, low for a smooth baseline; rendered-pose hold.** Contrary to the premise, the current implementation does **not** quantize the motion-controller clock. It selects a real/presentation clock (`indra/newview/alsteppedanimruntime.cpp:466`–`:475`), captures on part-group grids and overlays held poses (`:933`–`:948`), then restores smooth state after rendering (`:1005`–`:1035`; call at `indra/newview/llappviewer.cpp:1681`). Impact holds/adaptive/ease effects can extend a visible pause near a seam. The unrelated legacy controller quantum path exists (`indra/llcharacter/llmotioncontroller.cpp:888`–`:915`), but its avatar caller is disabled (`indra/newview/llvoavatar.cpp:5754`–`:5757`).

   **Confirm:** `StepAnimEnabled=false`; if needed log hold/capture/group tick at the seam. **Minimal fix:** select Smooth/off for the actor, or adjust the proven hold/adaptive policy. Do not modify the stock clock to fix a render overlay.

9. **Temporal / animation-factor changes — low unless a factor actually changes; time hiccup.** `setAnimTimeFactor()` forwards to a bare factor assignment (`indra/llcharacter/llcharacter.h:169`; `indra/llcharacter/llmotioncontroller.cpp:290`–`:293`), not a clock reset. Temporal clamps manual scale to 0–8, writes the global each active tick, and restores the saved prior global on release (`indra/newview/llpresentationtime.cpp:27`–`:28`, `:105`–`:117`, `:148`–`:175`). **It is not literally the sole writer:** Advanced animation speed also writes it (`indra/newview/llviewermenu.cpp:2098`–`:2104`). Returning to Live can restore an earlier non-1x value. Self Slow Motion separately sets local factor 0.2/1 (`indra/newview/llagent.cpp:290`–`:298`); ghost speed forwards to clone/animesh controllers (`indra/newview/llghostavatar.cpp:1768`–`:1788`). No factor setter is triggered by the native modulo branch.

   **Confirm:** Temporal Live, reset Advanced animation speed **after** leaving Manual mode, Self Slow Motion off; log both factors. **Minimal fix:** consolidate global ownership if competing writes are observed, or remove the unintended factor change. F32 timer/accumulator precision (`indra/llcharacter/llmotioncontroller.cpp:875`–`:887`) is a lower-probability long-session contributor, not a loop-specific trigger; use F64 accumulation only if measured zero/uneven deltas grow with uptime.

10. **CPU work at wrap / gaze — low for ordinary warmed loops.** The normal wrap performs modulo, key sampling, optional seam correction, and constraints (`indra/llcharacter/llkeyframemotion.cpp:785`–`:859`); it does not reload data, resend animation requests, recompute complexity, or rebuild LOD. Asset fetch/read belongs to initialization/load completion (`:543`–`:643`, `:3097`–`:3148`). Seam analysis is cached and normally warmed/preallocated on activation (`:742`–`:751`, `:1103`–`:1109`). Exception: enabling seam repair mid-play can defer cache population and defensive resize to the first wrap (`:1295`–`:1302`); not every subsequent cycle. Motion purge is per update and removes inactive motions (`indra/llcharacter/llmotioncontroller.cpp:190`–`:233`, `:880`–`:881`), not per loop.

   Stock asset constraints are a real conditional wrap-related path: they receive wrapped time, can deactivate/reactivate and change ease weight across the boundary (`indra/llcharacter/llkeyframemotion.cpp:855`, `:1591`–`:1607`, `:1707`–`:1709`); skeleton reinitialization instead depends on skeleton serial (`:1425`). Gaze paints after motion/Polish (`indra/newview/llvoavatar.cpp:5815`–`:5845`), feeds motors presentation time and target-generation events (`indra/newview/llactormover.cpp:7560`, `:8364`–`:8380`; `indra/newview/algazemotor.h:1202`–`:1217`). It does not consume the clip's loop point or reset its clock there. A changing animated head pose can change its correction, so a head-only symptom still warrants isolation.

   **Confirm:** correlate a wrap marker with CPU zones, constraint activation, cache misses, and restart counters; turn gaze off for a head-only hitch. **Minimal fix:** prewarm seam state when enabling mid-play; correct constraint windows/retain valid cyclic constraint state if their reactivation is measured; cache/move only work actually shown expensive. Repair gaze composition only if the post-gaze pose first introduces the discontinuity. No evidence supports a generic asset/complexity/LOD optimization as the loop fix.

**One discriminating user test, with outcomes specified beforehand**

1. Save current settings. In a quiet, fully loaded scene use a fixed camera and the offending inventory animation; start it once, let it warm for two cycles, then observe/record ten cycles. Disable viewer AO and scripted AO/dance devices, stop Dance Ball/Mover, disarm Switchboard, disable Director/Actor gaze. Leave attachment editing/pose freeze off.
2. Establish the stock-like baseline: `ALPolishEnabled=false`, `ALPolishLoopSeamEnabled=false`, `StepAnimEnabled=false`, `TemporalMode=0` (Live), `TemporalWorldScale=1`. After leaving Manual mode choose **Advanced > Character > Animation Speed > Reset All Animation Speed**; ensure `SlowMotionAnimation=false`. Test at 30 fps, then stable 60/uncapped with other settings unchanged. Use a capture rate sufficient to see the viewer frames; duplicate video frames alone do not prove a viewer stall.
3. Repeat with a verified simple seamless loop: e.g. a trusted 2 s single-arm sway, uniform keys, equal endpoint pose and matching endpoint velocity, loop [0,2], zero ease, no constraints. A convenient built-in dance is a comparison asset, not proof of a mathematically clean seam. Compare the same asset on self and on a nearby fully rendered real avatar (play in-world for others to see), and observe it in a stock SL viewer. Keep distance/visibility fixed; a mirrored clone is not an independent control.
4. Return to the offending asset. With the master on, keep all Polish subfeatures off; enable **only Loop seam** for ten cycles, then off and enable **only Inertia**. Then isolate Contact, Phase match, Secondary, and gaze as relevant. Separately compare direct playback against Mover/Dance Ball/Switchboard with fixed speed/phase and automatic changes disabled.

| Observed result | Interpretation |
| --- | --- |
| Baseline smooth; Loop seam alone adds one repeated pose/recovery | #1 supported; clock/CPU need not stall. |
| Inertia alone adds the hold | #3 supported; record jump/capture decisions. |
| Offending clip hitches with Polish off and in stock; seamless control does not | #2 or asset constraints strongly favored. |
| Only driver playback hitches; activation/stop/weight changes | #5; external sample discontinuity without restart instead favors #6. |
| Stable frame duration, one joint/body jumps while another subject stays smooth | Pose/layer discontinuity. |
| Whole frame/camera/subjects freeze, controller delta spikes | Real frame stall; locate work/wait/present cost before blaming modulo. |
| Only legs or only head change | Contact/foot phase or gaze composition; inspect before/after that layer. |

**Minimal instrumentation proposal — not implemented**

For **one avatar + asset**, buffer a few samples before/after each wrap and emit outside the measured hot path (or use Tracy numeric plots/messages). Detect native wraps with cycle index/decreased wrapped time, and track external cycle index separately; do not reuse `detectSeamWrap()` as the only instrument, because it misses #6. At `indra/llcharacter/llkeyframemotion.cpp:845`, before key application, record a marker such as:

Record asset bounds/key extrema/ease durations once. Keep wrap−2 through wrap+3 samples of one affected joint's quaternion/position **after raw keys, seam correction, final motion blend, Inertia, Contact, gaze, and rendered Stepped overlay**; derive angular/linear increments. Add activation/deactivation/stop counters at `indra/llcharacter/llmotioncontroller.cpp:1025`, `:1044`, `:465`, plus upstream sequence/cut/AO events only if counters change. This distinguishes advancing time with a duplicated pose, changed activation/weight, and a genuine delta spike.

Existing avatar zones cover controller/keyframe update (`indra/llcharacter/llmotioncontroller.cpp:867`; `indra/llcharacter/llkeyframemotion.cpp:770`); Stepped exposes `StepAnim::applyHeld` and `paletteRebuilds` (`indra/newview/alsteppedanimruntime.cpp:867`, `:958`), and limiter wait has its own zone (`indra/newview/alframelimiter.cpp:132`). Add a wrap marker and narrow `captureSeamPose`, cache-miss analysis, `applyConstraints`, and activation zones only where needed; correlate against the full frame including present. A log/zone duration spike caused by the diagnostic itself is **INCONCLUSIVE**. Repeated raw→seam/post-layer pose holds with regular time are **POSE**, activation/weight resets are **RESTART**, and measured extra frame work/wait is **STALL**; more than one can coexist.

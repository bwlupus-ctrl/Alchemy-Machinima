Implementation plan by Fable, 2026-10-05, for every item in `doc/DIRECTOR_CONSOLE_AUDIT_FABLE.md` section 5. Read-only: no source file was edited for this plan. Written incrementally, section by section.

**v4 changes (Codex plan review round 3, NOT APPROVED; two items -> revised):**
- D14: `ALToolPathEdit::handleDeselect()` now distinguishes an app-focus-loss deselect (lltoolmgr.cpp:458-468 calls `mSelectedTool->handleDeselect()` and leaves `mTransientTool` in place) from a real deactivation: it always resets drag / capture / walk-arm / menu, but clears the session owner ONLY when the tool is no longer the current tool (`!usingTransientTool() || getCurrentTool() != this`, lltoolmgr.h:52,71). On focus return the panel's toggle therefore stays on and the tool stays usable; ownership ends only on `setTransientTool` to another tool, `clearTransientTool`, or the owner's `endSessionFor`.
- D4: the safety rationale now says "formatted-string compare, unchanged" everywhere; no wording left that could be read as licensing the rejected numeric quantization.

**v3 changes (Codex plan review round 2, NOT APPROVED; round-1 items closed -> revised):**

The node menu captures {owner, actor, node} when it opens and its two deferred writers reject the callback unless all three still match. Every tool mutation path is enumerated with its owner validation.
- D4: the snapshot keeps the FORMATTED-STRING compare (`llformat` once per frame, 15 fields, not a widget write) so trigger timing is byte-identical to today; only the representation of the roster and the control writes change. V12 reworded.
- D10: orphaned source defined: when the source floater is not instantiated at pull time the gaze selection is CLEARED (`takeSelection(source, {})`), never kept from a previous source; checklist item 11b.
- D14 focus install: the path editor's control tree is static after XML build (no `addChild`/factory calls in alpanelpatheditor.cpp), and the ownership hook is additionally re-run on every reveal with a per-panel identity set so it is idempotent and covers any future dynamic control.

**v2 changes (Codex plan review round 1, NOT APPROVED -> revised):**
- D14: the draw-time ownership re-assert is DROPPED (ownership is purely event-driven; "focused host owns" is now a focus-received / mouse-down claim). The transient edit tool gets an owner (`ALToolPathEdit::mOwner`) and an owner-aware exit protocol. Every handler that touches `mEditNode` or the tool claims synchronously first (enumerated). A null actor is never claimed: a visible host with no selection releases.

- D7: the in-place deque iteration is DROPPED; only the cached column indices stay.

## 0. Conventions

**Tags.** Every item carries one of:
- **mechanical** - behaviour identical except removed redundant work or an added zone; a Sonnet batch with Codex review;
- **design** - a shared-state or layout decision; Codex plan review of this section before any code;
- **leave-alone** - not done, reason restated.

**Part C lessons applied throughout** (doc/UI_DRAW_PERF_PART_C_BRIEF.md):
1. no revision counter on publicly mutable or settings-backed models (`LLDirectorCast`, cast groups, `LLActorMover` paths, switcher banks) - nothing below adds one;
2. widget-exact diff semantics: every write goes through `aluirefresh.h` (`setTextIfChanged` compares after CRLF strip, `setValueIfChanged` compares what the widget would store, `setLabelIfChanged(LLButton)` compares both labels);
3. force on identity change: whenever a mirrored control's subject changes (selected actor, selected tab reveal) the pass runs with `force = true` so the focus guard cannot leave stale state;
4. focus guards cover descendants (`alIsBeingEdited` = `childHasKeyboardFocus || childHasMouseCapture`).

**The H1 helper, committed API** (`indra/newview/alscrollfit.h`, 299fef32c10; names used verbatim below):

Integration facts the Director plan depends on (verified against the committed code):
- **Commit callbacks append.** `LLUICtrl::setCommitCallback` connects a slot (lluictrl.cpp:1080-1084), so the Director's `onTabChanged` (llfloaterdirector.cpp:312) and the helper's refit coexist; the refit runs after `onTabChanged` because it is connected later. There is no ordering dependency: `onTabChanged` only writes settings and (D8) sets dirty flags, neither of which reads layout; the refit reads nothing `onTabChanged` writes. The Director does NOT call `fitAll` from `onTabChanged`.
- **Stretchers do not collapse any more** (`StretcherMins`, alscrollfit.cpp:143-156, recorded at wrap time :202-206), but the formula `need = old_h - r.getHeight() + min_h + FIT_PAD` assumes the stretcher sits inside the tab. A follows-all child DECLARED taller than its tab (the Ghost Studio at its 760-px root inside a 548-px tab) keeps its overflow through the wrap (`need` = 548 - 758 + 758 + 12 = 560, panel still 770 tall and 210 px below the document); a follows-all child pinned to fit (534 today) is recorded at ~532 and the document becomes 8 + 532 + 8 + 12 = 560 > 548, a permanent 12-px scroll with no benefit. Either way the Ghosts panel must become a top-follower for the wrap to do the right thing (D1).
- **Nested containers are reached.** `collectTabContainerTree` finds `ghost_studio_tabs` inside the Ghost Studio panel, so `installForTabs` also fits its four sub-tab documents (`place_scroll_body` 282, `style_scroll_body` 280, `pose_scroll_body` 790, `crowd_scroll_body` 604; panel_ghost_studio.xml:60-314, all follows left|top), appends a refit callback to that tab container and installs focus-reveal on those four containers. No other shared panel embedded in the Director contains a scroll container (grep over the 15 panel_*.xml files: 0), so the recursive `collectDocumentContainers` pass finds nothing further. The Lights document (`ALPanelCineLightRig`, follows all, not wrapped, so no recorded minimum) is fitted as a tab-level container regardless of API choice. Decision in D1.

### H2. Flow-grid cards sized from content (design)
- **Files.** `indra/newview/alflowgrid.h:29-51` (Params + members), `alflowgrid.cpp:35-52` (Params ctor), `alflowgrid.cpp:67-199` (`reshape`); `skins/default/xui/en/floater_director.xml:1110-1122` (the `<flow_grid>` node) is the consumer (D2).
- **Before.** `ALFlowGrid::reshape` packs columns by each card's DECLARED rect height (`CardLayout{card, card->getRect().getHeight()}`, alflowgrid.cpp:102) and reshapes each card to that same height (195). A card whose embedded panel is taller than the declared height draws over the next card in its column; one that is shorter leaves blank space (the Cinematic card: 456 declared, 28 + 303 + 8 = 339 real).
- **After.** New `Optional<bool> fit_cards` param, **default false** (the Cine Light Rig grid, panel_cine_light_rig.xml:9-21, must not change). When true, `reshape` first fits every card (visible and hidden) to its own children before the column packing: `need = max over direct children of (card_h - child.mBottom) + pad` for follows-top children, `child.mTop + pad` for non-following children, with `pad = mPad` (8, which reproduces today's "embedded + 36" = 28 title band + 8 bottom margin exactly), then `card->reshape(width, need)` keeping the top edge; only then `CardLayout{card, need}`. Same follows rules as `fitContainer`, so a card's children keep their positions. The function (`ALScrollFit::fitPanelToChildren(LLPanel*, S32 pad)`) is added to alscrollfit.h/.cpp as a free function (H1 is committed, so no collision); `fitContainer` is left as approved - sharing the math between the two is a later refactor, not part of this batch.
- **Why safe.** Default off: zero change for the Light Rig grid. For the Director grid the fit is idempotent across repeated reshapes (children follow top, so `card_h - child.mBottom` is invariant), and the result for six of the seven cards equals the hand-typed value today (676/640, 226 shot builders has no embedded panel: lowest child `hero_arc_ramp_strength` top 198 + 18 = 216 + 8 = 224, 2 px shorter than 226; 372/336, 250/214, 794/758, 1361/1325). The Cinematic card shrinks from 456 to 339 (D2).
- **Stale / break.** A card with a follows-bottom child would be measured by `mTop + pad` (none exist). A hidden card (none today) is still fitted, mirroring "preserve hidden cards' declared heights" (172-175). If a future embedded panel changes its own height at runtime, the next `reshape` (any floater resize) re-fits; nothing re-fits on its own, which is today's behaviour too.
- **User-visible.** Yes: Cinematic card loses 117 px of blank space; Shot Builders card 2 px shorter; the flow grid repacks accordingly (cards may move column).
- **Class.** design (Codex question: param-on-grid vs. explicit post-build call; this plan prefers the param because any later reshape re-fits).
